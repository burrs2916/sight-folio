一、结论速览

导出链路整体可用，六种格式（Markdown / EPUB / HTML / TXT / DOCX / PDF）全部能正常生成完整作品文件，后端三种二进制格式（EPUB / DOCX / PDF）均有 Rust 冒烟测试覆盖且实测通过、产物可被标准工具正确解析。备份与恢复功能也在同一链路中工作。

但“能导出”不等于“排版合格”。当前三种二进制格式的排版实现均存在明显的审美与规范缺口：PDF 无首行缩进/正文页码/粗体标题、封面未居中且无作者；DOCX 缺少 styles.xml（标题样式跨端不稳定）、无首行缩进、默认字体依赖打开端；EPUB 无任何 CSS、章节无标题层级、缺作者元数据。其中 PDF 表格导出一处确定性功能性缺陷（单元格标签残渣混入正文），属必须修复项。

总体判断：完成度约 70%——功能面已就绪，排版面需一次集中的“出版级排版补齐”方可达到对外展示/正式交付水准。具体问题与修复建议见第四、五章。

重要说明：「完结作品」页（PublishedScenesPage.tsx）是导出记录的管理页，提供取回定位、撤销、批量撤销、外部文件导入、改名改目录等操作，并非导出触发入口——导出一次后再次导出需回到写作台菜单操作。这是有意设计的职责划分，但若用户预期“在完结作品页里也能再导出”，属于待确认的产品预期差异。

三、各格式导出正确性验证

验证方法

  • Rust 测试实跑：cargo test 导出相关 10 条测试全部通过（EPUB 结构测试×3、DOCX 冒烟×1、PDF 冒烟×1 等），覆盖 zip/OPF 合法结构、CJK 字体嵌入、XML 转义、图片重写等。
  • 真实产物解包核验：将冒烟测试生成的 smoke.epub / smoke.docx 解包检查内容；对 smoke.pdf 解码内容流还原正文文本。
  • 前端生成器代码精读：md/html/txt 三条前端路径逐行审查（含 turndown 表格规则、HTML 转义、DOMParser 去标签）。
格式 核心结论 验证证据
Markdown 可导出 标题/段落/表格/加粗等结构完整保留；表格走 GFM 规则可复现 turndown 规则审查；无自动化测试（缺口①）
EPUB 正常 EPUB3 结构合法：mimetype STORED、container.xml→content.opf、spine 顺序、图片重写为包内路径、XML 转义均正确；最小书（无图无简介）通过 3 条结构测试通过 + 产物解包核验（OPF/manifest/spine/nav/章节 XHTML 齐全）
HTML 可导出 单文件含内联样式（居中书名、章节分隔、打印分页），书名/章节标题正确转义 源码精读（esc 转义、@media print）；无自动化测试（缺口①）
TXT 可导出 章节标题+正文纯文本，卷变化时插入分隔线，HTML 标签完整剥离 源码精读；无自动化测试（缺口①）
DOCX 可导出但样式残缺 OOXML 结构合法，图片确实嵌入 media/；但无 styles.xml、无首行缩进、无默认字号字体，标题样式依赖打开端 fallback 冒烟测试通过 + 解包核验（document.xml 全文检查：pStyle 引用未定义、无 w:ind、无 docDefaults）
PDF 可导出但有确定性缺陷 文件结构合法、CJK 字体真实嵌入（15MB 实测）、中文换行正确；但表格导出为标签残渣（见下） 冒烟测试通过 + 内容流解码还原正文：表格输出 td甲/tdtd乙/td
备份 正常 SQLite 整库快照，恢复导入可用 代码审查（备份非作品形态，字数/章数记 0）

★ 确定性功能缺陷：PDF 表格导出损坏

现象：含表格章节导出 PDF 后，表格内容显示为 td甲/tdtd乙/td 等“标签残渣+单元格内容”混排文本；原注释声称“行内单元格以 | 拼接”，但 clean_text() 实际只删除了 < 与 > 两个字符，未实现 </td> → | 的替换。

src-tauri/src/application/writing/pdf_export.rs:588-603（clean_text）· :565-573（表格行处理）

验证过程：① 阅读源码确认 clean_text 仅过滤尖括号；② 运行 Python 精确模拟 clean_text 对表格行的处理，复现 td甲/tdtd乙/td；③ 运行冒烟测试实际生成 smoke.pdf，解码其内容流（含 ToUnicode CMap 还原）后，正文中检出真实输出 td甲/tdtd乙/td、td1/tdtd2/td——三条独立证据一致。

影响：含表格章节（设定集、角色卡数据表等）在 PDF 导出时不可读，属阻断级功能缺陷。修复建议：在 clean_text 之前先将 </td> 替换为 | （DOCX 导出的表格展平已正确实现，可对照参照）。

跨格式补充观察

  • 图片资产引用模型：正文插图使用 src=asset://…（Tauri 私有协议）+ data-asset（相对引用）双属性。三种后端格式（EPUB/DOCX/PDF）均有 resolve_asset_ref 或图片提取逻辑，可将相对引用解析为绝对路径并嵌入/重写，实测 EPUB 图片正确进入包内、DOCX 图片进入 media/。前端三种格式未处理图片引用：HTML 将正文原样内联（asset:// 在外部浏览器不可见）、MD 经 turndown 输出 asset:// 原文、TXT 自然丢失图片（纯文本合理）——若导出 HTML/MD 后仍在第三方环境打开，配图会裂。属中等优先级一致性问题（见第五章 P2-2）。
  • 测试缺口：① 前端三种格式（md/html/txt）无任何自动化测试；② docx_export.rs、pdf_export.rs 除冒烟测试外无单元测试（EPUB 有 3 条结构测试）。PDF 表格缺陷未被发现，正是“只验结构不验正文”的测试盲区。
  • 异常路径：导出失败会 toast 提示且不落“完结作品”记录；用户取消保存对话框直接 return——流程健壮性良好。

四、排版审美评估（逐格式）

PDF 问题最多（7 项）

P0
表格导出为标签残渣
正文中出现 td甲/tdtd乙/td，既不可读也破坏排版观感（同第三章缺陷）。
P1
封面书名左对齐、无居中版式，且无作者信息
封面仅有书名+简介+“Sight Folio 导出”标记，全部从左侧 50pt 起排；无书名居中、无副标题层级、无作者署名，缺乏正式出版物封面感。
P1
正文无首行缩进、无正文页码
正文 11pt/1.5 行距、左右 50pt 边距，但段落无 2 字符首行缩进（中文小说规范）；页码只出现在目录，正文页没有任何页眉/页码。
P1
标题无字重区分
章标题 15pt、正文内 h1/h2 为 14/12pt，但仅嵌入单字重 TTF，标题与正文仅靠字号区隔，无加粗或层级色彩。
P2
目录点线固定、无卷层级
目录点线为写死的 "······".repeat(2)（固定 6 点×2），不随行宽自适应；卷/章无缩进层级，长书目录呈扁平长列。
P2
无章节分页控制
未见章首强制换页逻辑，章节间连续排布，阅读体感更像连续文档而非图书。

pdf_export.rs: build_cover_stream(616) · build_toc_stream(636) · append_text_line(368) · 正文 86 起

综合评级：★★☆（2/5） 结构正确、字体嵌入可靠，但版式处于“能用”而非“可读悦目”水平，封面与正文排版均需重做。

DOCX 关键问题（5 项）

P0
无 word/styles.xml，标题样式引用未定义
document.xml 引用 w:pStyle w:val="Heading1/Heading2"，但包内没有任何 styles.xml 定义这些样式——Word/WPS/LibreOffice 各自 fallback，标题是否加粗/多大字号完全依赖打开端，跨端观感不稳定。
P1
无首行缩进、无默认字体与行距
正文段落无 w:ind 首行缩进；无 docDefaults 设置字号/行距/中西文字体，默认落到打开端默认（如 Calibri 11pt），中文作品观感差。
P1
图片固定 4000000×3000000 EMU
插图固定约 4.2×3.15 英寸，长图/宽图会被拉伸变形，未按源图宽高比自适应。
P2
表格展平为文本行
表格被展平为 甲 | 乙 纯文本段落（可读性尚可），丢失真实表格结构，无法在 Word 中按列处理。
P2
无页眉页脚/页边距手感
sectPr 为 A4 + 1 英寸边距，无页眉页脚；行内样式仅支持 b/i/u/s/mark/br，链接与 code 被忽略。

docx_export.rs: document.xml 生成(90-121) · image_paragraph(589) · 行内解析(174 起)

综合评级：★★☆（2/5） 文件可打开、内容完整，但“样式未定义”是结构性隐患，Word 中打开的标题与正文观感不可控。

EPUB 关键问题（5 项）

P1
无任何 CSS：无全局字号/行距/首行缩进
章节 XHTML 直接渲染编辑器内联样式，包内无 stylesheet；正文字号行距完全由阅读器默认决定，同一书在不同阅读器观感差异大。
P1
章节正文无章标题（h1）
章标题只存在于 nav 与 <head><title>，章节正文首页直接是正文段落——除非正文内容里自带 h1。阅读器进入章节看不到标题。
P2
元数据缺作者（dc:creator）
OPF 元数据只有 title/language/description/identifier，无作者字段，图书信息不完整。
P2
无正式封面页声明
无 cover.xhtml / cover-image 元数据声明（书架缩略图缺失），章头图只是嵌在章节内。
P2
目录无卷/层级分组
nav.xhtml 为扁平 <ol> 一列到章，长书无卷分组、无二级嵌套。

writing/mod.rs: export_epub(271-490)

综合评级：★★☆（2/5） 容器结构规范（这点做得好），但阅读体验完全裸奔，缺 CSS 与章标题是影响最大的两项。

HTML / MD / TXT 相对均衡

P2
HTML/MD 图片引用不可外部解析
asset:// 为 Tauri webview 私有协议，导出 HTML/MD 后在浏览器/GitHub/语雀等第三方环境打开时插图无法显示（MD 输出 ![](asset://…)，HTML 内联原样）。TXT 剥离标签故不受影响。
P2
MD 无封面/简介区块增强
MD 仅 # 书名 + > 简介 + ## 章节，结构合理但不含目录或书籍元信息。
  • HTML 亮点：内联 CSS 完整（46em 阅读宽度、16px/1.9 行距、系统中文栈、居中书名、章节分隔线、打印分页），是四类“单文件”里版式观感最好的；章节省略号分隔配合卷标注有层次。
  • MD 亮点：GFM 表格规则正确（表头分隔行补齐），代码块 fenced，正文结构无损。
  • TXT 亮点：卷分隔线 ════ … ════ 视觉划分清晰，符合纯文本惯例。

综合评级：HTML ★★★☆（3.5/5）· MD ★★★（3/5）· TXT ★★★☆（3.5/5） 前端三格式见仁见智，差距主要在后端二进制格式。
