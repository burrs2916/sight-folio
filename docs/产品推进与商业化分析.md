# Sight Folio · 产品推进与商业化分析

> 分析日期：2026-10-28 ｜ 分析方式：源码走读 + Schema 清点 + 能力行数实测 + 市场检索
> 范围：产品定位、功能完成度、架构适配度、商业化路径。不涉及提交/分支等工程流程问题。

## 一、这个项目实际上在做什么

README 的定位是「面向长篇创作的桌面创作平台」。这个描述准确但没有指出真正的价值点。把 56 张表、写作域能力和 UI 入口摊开看，产品实际在做的事情比"写作软件"窄且深得多：

**它管的是"长篇叙事的一致性"，不是"打字"。**

| 能力 | 载体 | 解决的真实痛点 |
| --- | --- | --- |
| 伏笔账本 | `writing_foreshadowings`（plant_chapter_id / payoff_chapter_id / status）+ `writingForeshadowing.ts` + 到期提醒条 | 埋了不收，读者在评论区骂 |
| 剧情线 / 时间线 | `writing_storylines`、`writing_timeline_events`、`writingTimeline.ts`（全书/按章/剧情线三视图） | 多线并行时时间对不上 |
| 人物出场矩阵 | `WritingAppearanceMatrix.tsx` | 第三章死掉的人在第十二章又说话 |
| 世界观完整度 | `writing_settings` + `GenreMediumFields.tsx`（子类/完整度/矩阵） | 设定写了但正文没用 |
| 风格指纹 | `writingStyleFingerprint.ts` | 前后文风漂移、口癖重复 |
| 语料库句子级参考 | SQLite FTS5 + 输入即检索 + 指纹查重 | 长篇作者的语料沉淀无处可用 |
| 内置校对 | `writingProofread.ts`、`aiFlavorEngine`、`chapterAutoFix`、错字/重复/敏感词 | 交稿前的机械性错误 |

写作编辑本身（TipTap、快照、崩溃恢复、6 格式导出）是**必要的地板**，不是差异化——Scrivener、novelWriter、Manuskript、笔灵都有。

**结论性定位建议**：不要说"又一个写作软件"，要说**「长篇/连载作者的叙事结构体检仪」**。一句话可传播、可演示、且当前竞争者稀薄。

## 二、功能完成度（按证据，不按宣称）

| 支柱 | 完成度 | 证据与缺口 |
| --- | --- | --- |
| 写作台 | **高** | 649 个 writing 命名空间 i18n key；独立沉浸窗口（`writingDeskWindow.ts`）；快照 + 崩溃恢复；查找替换；导入 md/txt/html/epub/docx |
| 导出 | **约 70%** | 自有报告（2026-10-14）实测：6 格式全部可生成，但 EPUB 无 CSS、DOCX 缺 `styles.xml`、PDF 无首行缩进/页码，**PDF 表格输出为标签残渣（确定性缺陷）**，共 10 项 P0–P2 排版问题 |
| 语料库 | **中高** | 导入支持 epub/mobi/azw3/fb2/docx/html/md/txt（比多数同类强）；FTS5 句子级；指纹查重；`corpus.db` 已达 263 MB，说明有真实数据量在跑 |
| AI | **中** | BYOK 多供应商（`ai_providers/ai_models/ai_endpoints`，`AiAgentPage` 有 key 配置表单）；全书上下文注入；续写/润色/审阅 |
| 场景画布 | **低–中** | F 系列批次推进中；四块板（总览/分镜/关系/封面）为规划态，未验证 |
| **商业化基础设施** | **0** | 无账号、无授权/激活、无支付、无自动更新（Cargo 仅 opener/dialog/notification）、无遥测、无云同步 |

补充：`src/store/authStore.ts` 不是用户账号体系——它是 `WebhookConfig`/`AuthPreset`/token 存储，属于已封存的数据源域。目前**不存在任何用户身份概念**。

上手侧：`BookshelfPage` 有 `dashboard.emptyTitle/emptyDesc` 空状态，但**没有 onboarding、没有示例书、没有引导流**。第一次打开是一个空书架。

## 三、核心发现：投入与产品论点是倒置的

把代码行数按"是否服务产品论点"切开：

```
差异化能力（叙事一致性）  ~1,077 行   ← 伏笔 147 + 出场矩阵 236 + 风格指纹 295 + 时间线 316 + 世界观 83
继承的画布/场景渲染引擎   ~22,204 行   ← sceneEditor/canvas/renderers/spatial/layers/plugins
继承的代码分析后端        ~21,570 行   ← commands 层 74%（call_graph 5,777 / code_structure 4,920 …）
```

**产品赖以立足的那组能力，代码量只有另两块继承资产的约 1/40。**

这不是"代码多就是坏"，而是：每一次迭代预算、每一次重构、每一个新功能的复杂度上限，都在被那 43,774 行拖累，而真正的护城河只有 1,000 行。封存决策（2026-10-22）方向正确，但只封了启动链路——依赖、IPC 注册面、表结构、编译成本全都还在付费。

## 四、架构与商业化的适配度

### 4.1 架构已经做对的（不要动）

- **本地优先 + 数据可靠性地基扎实**：80 个 `CREATE INDEX`、FTS5、`VACUUM`/`ANALYZE`、`journal_mode=WAL` + `synchronous=NORMAL`、章节快照 + 崩溃恢复。对作者而言"不丢稿"是唯一不可协商项，这一层已达到可承诺商业产品的水平。
- **自研虚拟化**（`VirtualRows.tsx`、`virtualList.ts`，刻意不引第三方）——符合长文档场景。
- **双库分离**：`config.db` 2.3 MB（作品）/ `corpus.db` 263 MB（语料）。语料库是可独立分发、独立替换的资产。**这是别家没有的内容生意入口**。
- **插件机制已埋**：`PluginLoader.ts` + `HostAPI.ts` + `component_plugins` 表 + `get_enabled_component_plugins`。生态化的地基已经在，多数写作软件从未做到这一步。
- **BYOK 供应商体系**：没有推理成本负债，同时天然契合"未发布稿子不出本机"的隐私卖点。
- **i18n 双语各 7,864 键对齐** —— 海外发行的前置条件已经付过成本。

### 4.2 阻碍商业化的四个架构缺口

1. **没有更新通道**。装了 v0.1 的用户永远停在 v0.1。`tauri-plugin-updater` 未引入。桌面软件商业化的硬门槛。
2. **没有授权/激活层**。但好消息是：这可以做得极薄——离线签名的 license 文件 + 机器指纹即可，**不需要自建账号服务**，不必破坏本地优先定位。
3. **没有遥测**。目前所有功能优先级都靠自测判断，无法知道作者到底用不用"分镜板"。建议做**本地匿名功能计数 + 用户显式同意后才上传**（与隐私卖点不冲突）。
4. **AI 上下文引擎是双心智混体**。`src/ai/` 40 个文件里 `scan*` / `riskCorrelation` / `focusPatrol` / `metricTrend` / `entityRegression` / `requirementsSpecProvider` 服务代码扫描语境，`writingContextProvider` / `writingAssistant` / `writingCapture` / `writingMaterial` 服务写作。每加一个写作 AI 功能都要先理解一整套代码分析的心智模型——这是 AI 迭代速度的直接税。

### 4.3 备份策略需要升级（产品级风险，非架构洁癖）

`data/` 目录里现存 `corpus.db.bak-20261008`（77 MB）——**手工复制文件当备份**。当前唯一的用户侧备份是"手动导出 .db"。对以稿子为生命的产品，这应该是自动版本化快照 + 可选网盘/WebDAV 目标。这同时是"作者不敢从 Word 换过来"的第一阻力。

## 五、市场环境（2026）

**海外**：定价锚点已经分层清楚。

- Scrivener：$59.99 一次性 / 全平台 $147 —— 纯组织型工具走买断
- Sudowrite、Novelcrafter、Novlr、Squibler：$8–30/月订阅 —— 带 AI 的走订阅
- Campfire 模块化定价；Plottr $25/年起；Manuskript 免费开源
- AI 写作工具订阅区间大致 $4–129/月；story bible 类工具多从 $4/月起

**中文**：作者真实工作流是**组合拳**（CSDN 2026 多篇横评一致）：DeepSeek 做逻辑推演 + 笔灵 AI 做开篇破冰/全流程辅助 + 平台自带作家助手做发布。同时存在"一键生成 500 万字"型产品（唐库等），卖的是**替你写**。

**判断**：

1. 不要跟"AI 一键生成"抢用户——那是不同需求，且拼的是模型与成本，不是工具。
2. 不要跟平台自带作家助手抢"发布"——那是它们的原生地盘。要抢的是**发布之前的结构管理**，以及"稿子不上传到别人服务器"这个平台给不了的承诺。
3. **中文市场的空白恰好是 Sight Folio 已有的那 1,077 行**：长篇/连载中"别写崩"。竞争者少，且粘性极强——一个作者沉淀了 300 万字的伏笔账本、出场矩阵、语料库之后，迁移成本接近不可迁移。**这就是护城河，而它现在只有 1,000 行。**

## 六、商业化设计

### 6.1 定价结构（按投入产出排序）

| 层 | 内容 | 理由 |
| --- | --- | --- |
| 免费 | 写作台 + 基础导出（md/txt/html）+ 单机备份 | 写作软件没有免费入口就无法建立信任；作者必须先"把稿子放进来" |
| 买断 ¥149–199 / \$39–49 | 伏笔账本、出场矩阵、时间线/剧情线、世界观完整度、风格指纹、一致性体检报告、出版级排版导出（EPUB/DOCX/PDF）、自动版本化备份 | 低于 Scrivener 打差异；一次性付费对作者心理门槛最低；护城河全在这一层 |
| 订阅（可选，后置） | 托管 AI 额度（BYOK 保持免费）；语料包订阅；多端同步 | AI 是唯一有持续成本、也最适合订阅的东西。**先不代充 token**，否则负债先于收入 |
| 内容生意（架构独有优势） | 官方/社区语料包、题材套模板、世界观模板、风格分析预置 | 双库分离让 `corpus.db` 可独立分发；这是纯编辑器类产品做不了的第二曲线 |

### 6.2 冷启动最小闭环（一个季度）

按这个顺序做，每一步都直接对应"用户愿不愿意付钱"：

1. **先解决"不敢装"**：Developer ID 签名 + 公证 + Windows 代码签名 + `tauri-plugin-updater`。`docs/signing-publish-plan.md`（10-07）方案已写完，只差执行。产物瘦身：feature-gate 掉 sqlx/redis/mongodb/11 个 tree-sitter 语法，260 命令收收到写作实际需要的约 60 个。
2. **先解决"排版 70%"**：自有报告已列出 10 项 P0–P2 与 1 项 PDF 表格缺陷。出版级导出是买断层的核心理由，必须补齐。
3. **先解决"打开不知道干什么"**：加 3 分钟样板流——导入一本自己的书 → 自动产出一份"叙事一致性体检报告"（伏笔未收清单 / 出场矛盾 / 时间线冲突 / 高频重复）。这是唯一能一句话说清、当场演示、且别家没有的动作。
4. **砍掉未验证的重投入**：场景画布四块板（尤其"分镜板"）需要先验证需求再投入。若作者不用，22K 行的渲染引擎就是纯拖累，应降级为"全书总览 + 人物关系"两块有明确用途的板。

## 七、如果只做三件事

1. **打通发布链路**（签名 / 公证 / updater / 产物瘦身）—— 否则永远停在"开发中的应用"，而不存在"产品"。
2. **把「叙事一致性体检」做成一页可导出可分享的报告** —— 这是全部差异化价值的集中出口，也是唯一的市场切入点。
3. **补齐出版级导出** —— 决定作者愿不愿意掏钱的最后一公里。
