# 散文（essay）体裁适配审计 · 2026-11-08

李先生提的两件事：① 工作室目前只有小说、散文两个体裁实装，对不对？② 散文和小说本该不一样，
但点进散文作品后走的还是小说那套。下面每条都给了**代码位置**与**真机数据**，并标注是否由我本人逐行核对。

## 1. 你看到的现象，真机数据能直接复现

读 `data/config.db`（`sqlite3 -readonly`）：

```
id …   title       genre  medium      status
book_… 新建作品 2   novel  serial      draft
book_… 新建作品 1   novel  serial      finished
book_… 新建作品 3   essay  collection  draft     ← 散文这本

章节（writing_chapters）：
 新建作品 3 → 「第 1 章」 kind=篇  parent=-  word_count=0  content_len=0
 新建作品 2 → 「第 1 章」 kind=卷  parent=-  word_count=17
 新建作品 1 → 卷 1..4 (kind=卷) + 章 1..3 (kind=章，挂在卷 1 下)
```

散文这本一进来就是**一个标题叫「第 1 章」、kind 写成「篇」的节点**。这两个事实各自对应一条真因：

### P0-A 散文篇目点进去**不能写正文**（被当成"卷"这一层归类节点）

- `src/store/writingStore.ts:607-621`（我核对）：`createChapter` 把顶层节点 `kind` 设成
  `defaultLevels(genre)[0]` —— essay→`篇`，novel→`卷`。
- `src/utils/writingStats.ts:21,48-51`（我核对）：`STRUCTURE_KINDS = new Set(['卷','篇'])`；
  `isVolumeNode()` **只要 kind 命中就算容器**（`hasChildren` 只是兜底）。
- `src/pages/WritingPage.tsx:871` + `:3195-3197`（我核对）：`activeNodeIsGrouping = isVolumeNode(...)`
  → 渲染**只读** `VolumeOverviewPanel`，正文编辑器被 `display:none`（`:2990`）。

于是「零配置起步」（顶层按体裁命名）与「归类节点只读」（2026-11-07 那条）**互相打架**：
散文的「篇」既是正文单位又被认成容器 → 点进去是"卷概览"。
**这条不只影响散文**：`新建作品 2` 的顶层「第 1 章」kind=`卷`，同样命中只读分支。

### P0-B 散文书的第一篇叫「第 1 章」

- `src/utils/studioBook.ts:118`（我核对）：建书后 `createChapter(t('studio.firstChapter'))` —— 无体裁分支。
- 同文件 `:296-299` 另一条建篇路径**已经**会 `isEssay ? 'studio.pieceN' : 'studio.chapterN'`。
- 其它漏口（我核对）：`src/pages/writingPage/useDialogActions.tsx:123`、
  `src/editor/renderers/WritingDocsRenderer.tsx:135,638` 都用 `writing.newChapterName`（「第 {n} 章」）。

一条路径做对了、三条路径漏了 —— 典型的"分支没收口"。

## 3. 已经做对的散文分支（别再重复改）

`ESSAY_SHELF`（篇目/立意/便签，**不含** 人物与世界观）与 `shelfFor(genre)`；
`defaultMediumForGenre('essay') = 'collection'`；`GenreMediumFields` 切体裁自动联动载体；
`defaultLevels()` essay→`['篇','节']`；`writingPalette.chapterItem(genre)` 术语「篇目」；
`studioBook.ts:296-299` 建篇按 `isEssay` 命名；`WritingStudioPane`/`WritingDesignView` 的"大纲→篇目+立意"；
`WritingChapterEditor` 的 `unitEssay` 单位词；`writingExport` 走树先序而非硬编码卷章。

**结论：术语层与货架层做完了，结构判定层 / 面板层 / AI 层没做。** 这就是"点进散文还是小说那套"的全部来源。

## 4. 需要李先生拍板的四个口径（不定就只能按我的理解改）

1. **散文的「篇」是正文单位还是容器？**（P0-A 的根）我的主张：**容器=有子节点**（外加显式结构标记），
   `kind` 词表只用于命名，不再参与"能不能写正文"的判定。
2. **面板要不要按体裁裁剪？** 我的建议：散文隐藏 世界观/伏笔/剧情线，保留 篇目/立意/素材/便签/校对/统计/总览；
   「人物」「时间线」降级为可选（散文记人/记时也常见）。
3. **AI 提示按体裁分支的范围？** 最小做法：`InlineWritingContext` 加 `genre`，把「小说/网文/章」换成
   体裁中性词 + 按体裁选任务集（散文用 立意/结构/意象/语言节奏，不用 伏笔/人设一致性）。
4. **改体裁要不要迁移已建结构？** 我的建议：**不自动迁移**（会动用户内容），改成"检测到不一致就提示 + 提供一次性整理"。

## 4.5 追加发现（第二刀写测试时挖出来的，比页签本身更深一层）

**「这是不是一本书」的身份，借用了小说的语言标记。** 证据（我逐条读到原文）：

- `src/utils/studioBook.ts:75`：建书时给支撑场景写死 `primaryLanguage: 'novel-zh'` —— **不分体裁**，散文/诗歌/剧本都写这个值。
- `isBookScene = (scene.primaryLanguage === 'novel-zh')` 这个判定散布在 **12 处**：
  `SceneTabBar.tsx:161`、`SceneEditor.tsx:331`、`SceneEditorPage.tsx:444/677/1277`、
  `projectCanvas.tsx:124/913`、`PortraitLegend.tsx:56`、`ComponentCenterPanel.tsx:1816`、
  `ArchitectureLayersPanel.tsx:56`、`reportGenerator.ts:564/1133/1501`。

后果两条：
1. 散文只是**沾了那行写死的光**才长出 L2 页签栏。我把夹具的 `primaryLanguage` 换成体裁真实的
   `essay-zh` 试过一次：整条页签栏直接消失（`.MuiTab-root` 数量 = 0）。这条已做成**缺陷证据锁**用例。
2. `reportGenerator` 三处（HTML/JSON/SVG 导出）按 `novel-zh` 分流 —— 散文作品的导出走的是**小说报告**分支。

**建议修法（未做，属承载层，等拍板）**：给场景加独立的"书场景"标志位（例如 `projectKind: 'book'`），
把 12 处 `isBookScene` 与 3 处导出分流都改吃它，`primaryLanguage` 回归它本来的语义（语言）。
改动面：类型 + 建书 + 迁移旧数据（现有书全部补 `projectKind:'book'`）+ 12 处判定 + 导出报告。

## 5. 建议刀序（每刀独立可验）

1. **第一刀（P0-A，功能阻断）**：容器判定与 `kind` 命名解耦，散文篇目（和小说顶层章）恢复可写正文。
   属承载层：判定改了要回归 统计/总览/语料/导出/写作台 五处。
2. **第二刀（P0-B）**：建书/新建默认名按体裁走，并把四条入口收口到一个纯函数。
3. **第三刀（P1）**：页签/面板按体裁出配置表（一处定义，SceneTabBar/总览/左栏/体检共用）。
4. **第四刀（P1）**：AI 上下文与提示词按体裁分支（含"无人设不是缺陷"）。
5. **第五刀（P1）**：KPI/预警/语料口径按体裁（卷数→篇数、章均→篇均、散文关掉长短离群）。
