# 封存决策：代码分析工作台 + 数据源集成（2026-10-22）

## 背景

Sight Folio 从 biosphere-spatialdata-system fork 而来，正改造为「长篇创作平台」。
经全面评估（架构 + 完成度），fork 遗留的两大域与写作主线弱相关，但体量约占前端
25%-35%（`src/datasource/` 3896 行、`CodeWorkbench.tsx` 3033 行、`projectStore.ts`
1367 行等），后端还拖着 `sqlx` / `redis` / `mongodb` / `tree-sitter` 重型依赖，
持续增加编译时间、维护成本与认知负担。

## 决策

**封存降级**：保留代码、停止投入、从启动链路摘除。不删代码（区别于"彻底移除"），
后续视产品需要可作为可选插件方向重新评估。

## 封存范围

| 项 | 处理 | 位置 |
|---|---|---|
| 应用启动数据源加载 | 不再执行（`loadFromBackend` 会对已配置连接真实建连） | `src/App.tsx` `SEAL_LEGACY_DOMAINS` |
| 代码分析域文件监视 | 不再随启动挂载 | `src/App.tsx` `SEAL_LEGACY_DOMAINS` |
| README 功能状态 | 🔶 fork 继承资产 → 🗄️ 封存 | `README.md` |

## 明确保留（不在封存范围）

- `/analyzer` 路由与导航入口 —— 它承载的是**场景画布**（写作主线支柱）
- 书场景右栏三栏（组件/属性/AI）—— 纯写作功能
- 分析调度心跳 —— 同时服务写作域洞察（scope：分析 > 书籍）
- AI 面板 `onOpenPath → spawnCodeWorkbench`、代码场景右栏分析 tab、
  画布数据绑定引擎 —— 代码原样保留，仅不再主动初始化

## 恢复方式

`src/App.tsx` 中 `SEAL_LEGACY_DOMAINS` 改回 `false` 即恢复原启动行为。

## 后续待办（封存不等于永远）

- 若确认永不恢复：删代码 + 移除 `sqlx` / `redis` / `mongodb` / `tree-sitter` 依赖，
  预期显著缩短编译时间并减小安装包体积
- 若走向插件化：需先把代码工作台与数据源从 `SceneEditorContext` 的深度耦合中解出边界
