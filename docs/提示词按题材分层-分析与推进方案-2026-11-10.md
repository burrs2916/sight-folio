## 0 结论先行（三句话）

1. **病灶不是"提示词写得不够好"，是结构错了。** 提示词层的体裁判据是 4 个布尔函数（`isEssayGenre / isPoetryGenre / isScriptGenre / isDiaryGenre`）+ **同一套 if 链在 6 个地方各抄一遍**（[writingAssistant.ts:116-129](../src/ai/writingAssistant.ts:116)、[:343-358](../src/ai/writingAssistant.ts:343)、[:440-455](../src/ai/writingAssistant.ts:440)、[:504-519](../src/ai/writingAssistant.ts:504)、[writingMaterial.ts:104-108](../src/ai/writingMaterial.ts:104)）。这种形状**必然**漏：漏一处的后果不是报错，是**静默掉进小说兜底**。
2. **这个后果已经真发生过一次**：剧本 2026-11-09 开闸时只开了术语层与工作台命令层，提示词层一支没加，于是 `script` 一路掉进小说兜底，模型收到的是「你是一位**网文写手**…分成自然段落…800～2000 字」（[writingAssistant.ts:88-98](../src/ai/writingAssistant.ts:88) 的注释把这件事写得很清楚，兜底文案在 [writingMaterial.ts:100](../src/ai/writingMaterial.ts:100) 附近）。**它会让模型把一出戏排成散文段落** —— 这不是叫法不准，是产物被改坏。
3. **正确做法本仓已经有了，只是没推广。** 语料层的单位名词早就是**查表**：`CORPUS_NOUNS[genreDef(genre)?.id] ?? novel`（[writingCorpus.ts:543-544](../src/utils/writingCorpus.ts:543)），并且注释写明"判据只有一份，这里只放双语措辞"。提示词层该向它对齐：**一张穷尽五种体裁的表，槽位固定，内容按题材写**。TS 用 `Record<WritingGenre, Pack>` 就能让"漏一个体裁"变成**编译不过**，而不是靠人记着补。

## 2 根因（三条，都在结构上，不在文案上）

**根因一：判据真源与提示词层断开。**
`writingSchema.ts` 已经把"这个体裁有没有卷、能不能建人物卡、用什么单位词、按不按日期写、要不要结构检查器"全部判完；提示词层却自己写 4 个布尔、6 条链。于是同一件事有两份答案，其中一份（提示词）**没有跟随开闸更新**——剧本那次就是这么掉的。这是本仓第一病灶「真源分身」的第 N 次发作。

**根因二：分支链没有"穷尽"约束。**
`if (poem) … if (scene) … if (entry) … return essay ? A : B` —— 新体裁加不加这一支，编译器和测试都不知道。兜底分支把错误吃掉了。

**根因三：题材差异只落在**措辞**，没落在**评估标准与输出契约**。**
诗真正要防的是"模型顺手把三行合成一段"（[writingAssistant.ts:80-82](../src/ai/writingAssistant.ts:80) 已经写明），日记要防的是"模型替作者编记忆"（[:101-106](../src/ai/writingAssistant.ts:101)）。这两条是**硬约束**，现在是以"再补一支 if"的形式散落在各条 prompt 里，而不是表里一个叫 `preserve`（不许动什么）与 `outputContract`（输出形态）的槽位。措辞是面子，这两个槽位才是里子。

## 3 目标结构：一张穷尽表 + 固定槽位（不是五份 prompt 文件）

新增 `src/ai/genrePromptPack.ts`，**类型上强制穷尽**：

```ts
import type { WritingGenre } from '../utils/writingSchema';

export interface GenrePromptPack {
  /** 正文单位的名词：诗=诗作 / 剧本=场次 / 日记=条目 / 散文=篇目 / 小说=章节 */
  unit: () => string;
  /** 一句身份。禁止再出现「网文写手」这种自带篇幅与套路暗示的头衔 */
  role: () => string;
  /** 【里子①】这个题材不许模型动什么 —— 越界就是改坏产物 */
  preserve: () => string;
  /** 【里子②】输出形态契约（换行、缩进、对白归属、日期锚点） */
  outputContract: () => string;
  /** 体量口径：诗歌与日记不许听到「800~2000 字」 */
  lengthHint: () => string;
  /** 审校/诊断镜头：这个题材里什么算信号、什么算噪音 */
  reviewLens: () => string;
  /** 上下文喂法：要不要前后文、要不要设定卡、要不要时间线 */
  feed: { neighborContext: boolean; settingCards: boolean; timeline: boolean; foreshadow: boolean; storyline: boolean };
  /** 自动化项白名单；表外项**不跑，并且要说**（见 §5） */
  automation: { meaningful: string[]; meaningless: string[] };
}

export const GENRE_PROMPT_PACKS: Record<WritingGenre, GenrePromptPack> = { novel, essay, poetry, script, diary };
export function genrePromptPack(genre?: string | null): GenrePromptPack; // 只在这里兜底一次
```

四条设计约定，每条都是为了堵一次已经发生过的错：

1. **`Record<WritingGenre, …>` 穷尽**：新体裁开闸时不写全这张表就编译不过 → 把"补一支 if"从纪律变成机制（根因二）。
2. **判据仍归 `writingSchema`**：pack 里**不许出现** `genre === 'poetry'` 这类字面判断，也不重新判定"有没有卷"。pack 只回答"**怎么说、要它做什么**"。谁需要"能不能建人设卡"仍然问 `characterCardsOptionalForGenre`（根因一，与 [writingCorpus.ts:497](../src/utils/writingCorpus.ts:497) 已声明的铁律同一条）。
3. **兜底只在入口一次**：`genrePromptPack()` 里 `未设置/未开闸 → novel`，与历史行为逐字等价；**删掉各槽位自己的 `?? 小说` 二重兜底**。今天的问题正是"6 处各兜一次"，其中一处漏了就没人知道。
4. **文案进 i18n 双包，函数只出键**：延续现有 `L(zh, en)` 效果但把散落的字面量收进键表，本仓已有 `i18n-en-output` 测试锁中英文，能直接复用这套门禁（避免"表在 TS 里写两份语言"变成新真源）。

**改造后每个调用点只剩一行查表**：`writingAssistant.ts` 6 条链、`writingMaterial.ts` 草稿/资料分析 2 条链、`workbenchContext.ts` 的分支全部塌成 `const p = genrePromptPack(ctx.genre)`。

## 4 五个题材分别怎么写（这一节就是你问的"提示词如何写"）

写法统一按五问：**本体是什么（不可让渡）→ 单位 → 不许动 → 输出契约 → 审校镜头 → 喂什么上下文 → 自动化哪些项无意义**。

### 4.1 小说 novel（= 今天的兜底口径，逐字保号）
- **本体**：情节因果 + 人物弧 + 时间线。它的价值在"前后相干"。
- **单位**：章节（可有卷层）。
- **不许动**：情节事实、人物行为动机、时间线顺序、已埋伏笔的回收位置。
- **输出契约**：自然段落；对话按叙事标点；不擅自加小标题。
- **审校镜头**：因果断裂、人物走形不走神、伏笔埋而不收、时间线冲突、重复用词。
- **喂**：前后章尾部 + 人设卡 + 时间线 + 伏笔 + 剧情线（全开）。
- **自动化**：全跑。唯一保持现状的题材——**因为其它四套都是从它这里分叉出去的**。

### 4.2 散文 essay
- **本体**：**一篇一个气口**（语气与思绪的连续），不靠情节因果。改写最容易毁掉的是节奏，不是事实。
- **单位**：篇目（集子平铺，无卷层——`isCollectionGenre`）。
- **不许动**：句序体现的呼吸、虚词与重复（散文的重复常常是故意的）、篇内的"闲笔"。必须明写一句："**删掉看似冗余的句子前先假定它是有意为之**"。
- **输出契约**：保持段落切分与原有的长短句对比；不为了"整齐"合段。
- **审校镜头**：意象/论述是否中途换轨；**不判章均体量离群**（`outlierMeaninglessForGenre=true`，schema 已定）；人设卡缺失不算缺陷。
- **喂**：本篇为主，前后篇只给标题不给正文（散文之间本就不承接，喂了反而诱发"串台"）。
- **自动化**：跳伏笔回收 / 跳剧情线 / 跳时间线冲突；保留错字标点、风格一致、篇内重复。

### 4.3 诗歌 poetry
- **本体**：**分行与节次就是本体**。[writingAssistant.ts:80-82](../src/ai/writingAssistant.ts:80) 已经把这句写在注释里，但它现在只是一条补丁，不是契约。
- **单位**：诗作（行/节不是章/段）。
- **不许动**：换行位置、节次、跨行断句（enjambment）、标点缺失（许多诗故意无标点）、字数密度。prompt 里要用**命令式**写："不得将多行合并为段落；不得补全标点；不得改写行尾断句处"。
- **输出契约**：返回文本**逐行保留换行**；不得包成 HTML 段落；如建议修改，逐行给"原行 / 建议行"两行对。
- **审校镜头**：意象重复与互斥、节奏（音节/顿数）起伏、跨行是否断在弱词上；**不判段落超长、不判连续空行**（诗的节间隔就是空行）。
- **喂**：同一首诗全文（不截尾——截尾会把诗砍断）+ 诗题；默认不喂人设卡与时间线。
- **自动化**：`LongParagraph` / `BlankLines` 两条格式体检对诗无意义（**注意：这是格式层的事，本方案不改判定，先保证提示词不拿它们当缺陷去“修”诗**）；跳伏笔/剧情线/章均离群。

### 4.4 剧本 script
- **本体**：**对白 + 舞台指示**，且对白必须有**说话人归属**。结构是幕›场（`structureInspectorForGenre='script'`）。
- **单位**：场次。
- **不许动**：说话人与对白的对应关系、幕场编号、舞台指示与对白的两类分界、台词的口语度（角色不文学）。
- **输出契约**：说话人行顶格、紧接台词；舞台指示统一括注样式；**绝不把对白转述成叙事段**（这就是 11-09 那个 bug 的正面版本）。
- **审校镜头**：对白性格化（人物能不能互相说对方的台词）、潜台词 vs 直说、**舞台可行性**（换景次数、在场人数）、场次体量差异（剧本里是真信号，schema 已论证）。
- **喂**：本场 + 上一场尾部 + 人物表（剧本的人物表比人设卡更合适，只给"谁在谁不在"）；不喂伏笔账。
- **自动化**：跳伏笔回收与时间线冲突（剧情在场上推进）；保留错字/标点/人名一致。

### 4.5 日记 diary
- **本体**：**当时的记录**。它的价值是真实与当下视角，不是文学性。
- **单位**：条目（按日期，`writesByDateForGenre` / `hasTodayEntryMode` 已有判据）。
- **不许动**（[writingAssistant.ts:101-106](../src/ai/writingAssistant.ts:101) 已经立过规矩，这里升为契约）：**不得增补原文没有的场景、对话、心理与因果**；不得把"我记得"改成"我知道"；不得把当天之后的信息写回当天（事后补写是最隐蔽的越界）。
- **输出契约**：第一人称、过去时态与原文一致；不添小标题、不分章；日期锚点保留。
- **审校镜头**：只校错字标点与语句歧义；**不校情节完整度**（日记的碎片不是缺陷）。
- **喂**：当天条目 + 近几天标题（只供"提过的人名"对齐）；不喂人设卡（`characterCardsOptionalForGenre` 含日记）、不喂剧情线。
- **自动化**：跳伏笔/剧情线/体量离群/风格指纹（日记风格本来天天变）；保留错字与标点。

> 一句话总结这五套的差异：**小说防改坏因果，散文防改平呼吸，诗歌防改散分行，剧本防改散归属，日记防改出不存在的事**。提示词的主体就应该是这五句话的展开，而不是今天的"网文写手 800～2000 字"。

## 5 三个界面层怎么接

### 5.1 工作室关键属性（已基本正确，只差"把属性说给模型听"）
属性本身归 `writingSchema`，不改。要做的是**把已有判据翻成提示词里的一句话**，让模型知道它在处理什么：
- `unitNameKey/unitShortKey` → 单位名词（现在这条已经靠 if 链在实现，改为查表）；
- `carrierTermKeys(genre, medium)` → 卷层说法（连载"部章结构"、集子"篇目"、剧本"幕场"）；
- `kpiLabelKeys(genre)` → 统计口径名词（KPI 标签已是表驱动，提示词直接复用）；
- `shelfFor(genre)` → 书架槽位名词（校对总览与详情的分区标题应与它同源，不再各写一遍）；
- `canCreateEntityForGenre` / `hiddenViewKindsForGenre` → **不该存在的实体就别向模型申报缺失**（`characterCardsOptionalForGenre` 已是这个思路的落地，推广到上下文组装层）。

### 5.2 右栏三面板
| 面板 | 现在 | 改法 |
| --- | --- | --- |
| 校对总览 | 体检判定与提示词都不分题材 | 判定层不动（格式/错字对五类都成立）；**送 AI 的"发现清单"按 `pack.reviewLens` 重排优先级并附一句本体裁的判断口径**（诗的空行不是缺陷，先说清再让它改） |
| 详情 | 按题材隐藏不适用页签（schema 已做） | 面板给 AI 的摘要只报"该题材真实存在的槽位"，不再报空段 |
| AI 助手 | 七段小说口径全量装配 | 按 `pack.feed` 装配（诗歌/日记不喂伏笔与剧情线）；空段**整段不出现**（现在会带一个空标题进上下文，模型会自己编东西填） |

### 5.3 写作台设定 / AI 语料 / 素材库 / 笔记
- **语料**：已是表驱动，只需把单位名词与 §4 的名词表**合并成同一份**（今天 `CORPUS_NOUNS` 与 `chapterLabelLine` 是两份，这是真源分身，必须并）。
- **素材库**：资料分析的 6 条输出维度（人物/情节/感官细节…）是小说口径 —— 剧本要"对白可用的台词素材与舞台调度"，日记要"当天真实发生的事，不得推测"，诗歌要"意象与语感素材，不要情节化"。这是 §4 表里 `role/outputContract` 之外新加一个 `materialDigest` 槽位。
- **笔记/念头池**：念头池对日记与诗歌的意义不同（诗的"念头"常常就是一行）。这轮**只把单位名词与输出契约接上**，念头池的语义分级列为 §7 P6 待拍。

## 8 不做清单（防跑偏）

1. **不为每个题材建一份 prompt 文件**：那会把"6 处链"变成"5×6 处文案"，改一个约束要跑五个地方。
2. **不做运行时"让模型自己判断体裁"**：体裁是作者在书架上定的事实，不是推断题；推断一次错一次。
3. **不新增表、不改快照指纹、不碰已锁版本**：提示词不进 `content_fingerprint`，历史产物不受影响（这条必须写明，免得被当成需要重新封存版本的改动）。
4. **不碰 §9 已冻结的七段体检判据**（尤其 2026-11-07 撤除的「章账」组：空节点不是缺陷）。本方案只决定**哪些发现值得送到模型面前**，不改哪些发现值得报出来。
5. 全程不 `git commit` / 不 push。

## 9 与「AI 助手批次 6」的关系

`docs/AI助手推进记录.md` 里挂着的批次 6（提示词重构，第 0 层）等的是"先给方案"。本文就是那份替代方案，且比原设想范围更准：**问题不在提示词措辞质量，而在判据没有单一真源、题材没有穷尽约束、自动化层根本不认题材**。批次 6 的其余未接入项（②③④⑤⑥）等刀 1-2 落地后再逐个接表，不并列开。
