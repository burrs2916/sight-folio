# 自动化任务提示词 · 五题材提示词分层持续推进（2026-11-10）

用途：登记成一个**定时 Agent 任务**，让它按固定节奏自转，每轮推进一小步、重新分析问题、再改进。
配套方案：[提示词按题材分层-分析与推进方案-2026-11-10.md](提示词按题材分层-分析与推进方案-2026-11-10.md)（判据与切刀定义在那份文档，本文件只管"任务怎么指挥"）。

---

## A. 先说清楚这份提示词为什么这么写（6 条设计要点）

1. **定时任务每次都是新会话，看不见我们现在这段对话。** 所以提示词必须**自包含**：绝对路径、门禁命令、红线、状态文件位置全部写在正文里，不许出现"接着上面继续"。
2. **进度不能只存在聊天里。** 必须有一个**状态文件**当唯一真源（本仓第一病灶就是真源分身），每轮先读它、末尾写它。否则跑三轮会出现三份互相矛盾的"我以为做到哪了"。
3. **一轮只闭合一个最小可验证单元。** 你原话是"不停地完成一次，然后重新分析它哪里有问题，再改进"——所以每轮的产物是「一小步改动 + 一次证据 + 一份新发现的下一轮清单」，**不是"把整件事做完"**。一轮想做完五刀，结果一定是五刀都没改干净。
4. **红线必须前置在提示词里，不能指望它自己想起。** 不 commit、删除铁律、入口铁律、四道门禁、不许削弱既有断言、假绿零容忍——每轮都重贴一遍，因为它每次都是新的脑子。
5. **要能自证，不许自嗨。** 每轮必须报数字（门禁实测值、快照 diff 组数、grep 命中数），并写"我没做什么/还有什么没做"。凡是只能得出"看起来对了"的判据一律不算完成。
6. **要有终止条件。** 五刀全绿 + 六判据过后自动转**守门模式**（只巡检、只报漂移、不再改代码）。没有这一条，它会一直找事做，把稳定代码反复折腾。

## D. 调度建议

| 项 | 建议 | 理由 |
| --- | --- | --- |
| 频率 | 每天一次（低峰跑，例如 03:30），或你上线时手动触发 | 一轮含 4 项门禁 + 全量 vitest + 反证，天粒度刚好；小时级会让门禁互相抢 CPU |
| 首轮 | 先手跑一次刀 1-1（只建表 + 穷尽实验），确认基线建立正常，再交给定时 | 定时任务第一轮最容易在"基线到底是多少"上出错 |
| 超时/失败 | 一轮跑不完不算失败：状态文件里保留队列，下一轮接着取队首 | 队列在文件里，不在会话里 |
| 并发 | 靠状态文件「进行中」认领位（等价于你仓里既有的 `docs/.round-claim.json` 惯例） | 两个会话同时改提示词层，一定出一份自相矛盾的表 |
| 汇报 | 每轮只回四件事：结果 / 证据 / 下一轮 / 待拍板 | 你要的是可持续，不是每次一份长报告 |
