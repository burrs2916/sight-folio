### 缺陷 A ｜ 写作台窗口的「查看完结作品」破坏「一书一窗」不变量（用户可见）

> 订正：本条初稿判成「点成空屏」，复核 `App.tsx:80` 的判定后**推翻**——窗口形态判定要求 pathname 以
> `/writing` 开头，跳转后判定翻转，页面照样渲染。以下是复核后的事实，不是「看不见的问题」。

证据链（全部本轮读码核对）：

1. 写作台窗口 URL 带 `desk=1`（`writingDeskWindow.ts:57`），**一书一窗**、label = `writing-desk-{bookId}`（`:22` 注释，10-09 拍板）。
2. `App.tsx:80-86` `isWritingDeskWindow(pathname)` = `pathname.startsWith('/writing')` **且** query 含 `desk`；`App.tsx:129-130` 据此选沉浸分支。
3. `LockVersionDialog.tsx:77` / `useExportActions.ts:134` 的 toast 动作是裸 `navigate('/published')` —— 一步同时改掉 pathname 与 search（`?desk=1` 被丢掉）。
4. 于是该窗口判定翻转 → 走主壳分支 → `/published` 命中主壳路由表（`App.tsx:335`）→ **无 chrome 的沉浸写作窗口原地长出侧栏 + 顶栏**。

三处实际后果：

- **专属写作台回不去**：label 仍绑着这本书，`openWritingDesk`（`writingDeskWindow.ts:97-106`）见 label 已存在就只 `emitTo('writing-desk-focus')` + `setFocus()`；而 WritingPage 已卸载、**没有消费方** → 之后从书架/顶栏点「打开写作台」只是把这个停在成品页的窗口置前，该书的写作台要等这扇窗关掉才能重开。
- **主窗口也补不了位**：全站没有任何入口把主窗口导航到 `/writing`（`grep "navigate('/writing" src` 零命中），主壳路由表里那条 `/writing` 是死条目。
- **跨窗事件凭空多出一个消费者**：`App.tsx:225-233` 的 `desk-goto-view` 监听以 `[location.pathname]` 为依赖、且 `if (isWritingDeskWindow(...)) return;` —— 形态翻转后这扇假主窗口**开始消费本该只有主窗口消费的章级跳转事件**，各自 `applyDeskGotoView` + `setFocus()`：写作台点一下提醒条，两扇窗一起跳并互抢焦点。

根因口径：**这两条 toast 绕开了仓内既有的「按窗口形态分发跳转」约定**——`utils/writingDeskJump.ts:105-113` 的 `dispatchChapterJump` 早就是标准答案（desk 窗口 emit 让主窗口接管，主窗口就地执行）。跳转这件事因此有了第二个写者：路由跳 vs 事件跳各走各的。
**为什么 3704 条测全绿拦不住**：`LockVersionDialog.test.tsx:196` 断言的是 `expect(navigateMock).toHaveBeenCalledWith('/published')`——路由器被 mock，窗口形态、label 绑定、事件消费方都不在测的视野内。测的是「入口存在」，不是「入口落点正确」。

### 缺陷 B ｜ 删书不清理版本与产物记录（数据账目）

- `src-tauri/src/infrastructure/database/writing_repository.rs:453-477` 的删书级联清单是 8 张 `writing_*` 表，**不含 `work_versions` / `work_version_chapters` / `export_artifacts`**；`commands/writing.rs:45-74` 的 `delete_writing_book` 只额外清了分析派生数据。
- 库层没有兜底：`migration.rs` 里 work_version 三表**无 FOREIGN KEY、无 TRIGGER**，只有 `ux_wv_book_seq` / `ux_wv_book_final` 两条唯一索引。
- 后果：删书后版本头与**全量快照正文**永久留在 `config.db`；成品页按书生成卡片，所以这些账**在界面上看不见、也就删不掉**（长篇一部书的快照正文可达数 MB）。需求 §5.3 明写「书被删 → 版本与产物记录级联删除（文件保留）」。

### 附带洞（小）｜「缺失」角标是被动状态

`list_export_artifacts` 不探磁盘，`status='missing'` 只在 `reveal_artifact` / `copy_artifact_to` 失败时改判。于是**换过作品库根目录后，产物会一直显示 ready**，直到你去点「取回」。§9-10 的验收只测了点取回之后，没测「列表呈现时」。
