创作台页面重设计分析

Sight Folio · 前端工程（Tauri + React + TypeScript + MUI）· 分析对象：创作台页面
日期：2026-10-08 分析方式：代码走读 + 现状梳理 范围界定：创作台 = /writing 路由「写作台」页 结论：重设计为三段式工作台框架

1 · 对象界定：什么是「创作台」

本项目用户语境下的「创作台」即前端 /writing 路由渲染的 写作台页面（导航文案「创作」，组件 src/pages/WritingPage.tsx，3263 行）。它是用户日常创作小说的主工作区，也是此前「写作中输入即自动检索语料库句子、固定区域实时展示参考」闭环（src/pages/writingPage/CorpusReferencePanel.tsx）所在的页面——两者是同一个页面，不存在独立的「创作台」与「写作台」两个界面。

该页面支持两种挂载形态：

  • 主窗口内嵌：左侧 SideMenu + 顶栏 AppNavbar 包裹，路由 src/App.tsx:199；
  • 独立写作台窗口：无 chrome 沉浸窗口（src/utils/writingDeskWindow.ts），同页消费 query 定位参数（src/App.tsx:153）。

重设计需同时覆盖两种形态：独立窗口去掉了外层导航，页面自身的栏目结构就是它的全部界面。

2 · 现状梳理

2.1 整体框架：固定宽左栏 + 弹性右栏（三栏语义，实际两栏）

左栏 280px（仅 normal 模式）
头栏：写作台标题 + 5 图标入口（解析全书 / 统计 / 出场矩阵 / 回收站 / 新建作品）
书架列表（≤45% 高度，滚动）
Tabs：章节 / 设定 / 笔记
章节 tab：搜索 + 导入 + 批量 + 新建 + 全文检索 + 章节树（拖拽排序）
设定 tab / 笔记 tab：列表 + 筛选 + 新建
右栏（编辑区，flex:1）
Tabs：正文 / 章详情
工具栏（15 项格式化 + 20 项功能图标，单行 flexWrap）
提醒条 ×4（伏笔到期 / 灵感 / 校对发现 / 统计）
章节标题（点击改名）+ 卷 chip + 状态/层级徽章
编辑器（Tiptap，zen/focus 居中收窄）
语料参考面板（输入自动检索，固定区，≤240px）
底栏：选区字数 / 今日进度 chip / 总字数
浮层：速记 FAB（右下）+ 十余个对话框/弹层（AI 审视、AI 聊天、快照、统计、校对、速记、查找替换、全书搜索、导入 TXT、回收站、快捷键、导出菜单…）

2.2 左栏：职责过载的四大功能区

  • 书架：作品列表常驻（WritingPage.tsx:1475），顶部 5 个全局操作图标（解析全书 / 统计 / 出场矩阵 / 回收站 / 新建作品）；
  • 章节 tab：操作行（全书搜索、导入 TXT、批量管理、新建章节）+ 标题/正文全文检索 + 章节树 ChapterTreePanel（拖拽排序、大纲绑定）；
  • 设定 tab：人设卡 / 世界观条目列表，选中后右栏切换为设定编辑区；
  • 笔记 tab：全书级灵感笔记列表（绑定章节 / 标签 / 置顶）。

四个职责共用一个 280px 栏，靠顶部 Tabs 切换；书架列表以「低频切换作品」的身份常驻占去近半高度，挤压频繁使用的章节树。

2.3 右栏编辑区：六层垂直堆叠

  1. Tabs 栏：正文 / 章详情；详情页切换为 ChapterDetailsPanel；
  2. 工具栏：左侧格式化组 15 项（useToolbarButtons）+ 右侧功能组约 20 项（章导航、专注模式、速记、快照、导出菜单、快捷键、AI 审视 / 聊天 / 自动审阅、查找替换、校对、AI 续写 / 润色），单行内 flexWrap 平铺；
  3. 提醒条 ×4：伏笔到期 ForeshadowReminder / 灵感 InspirationReminder / 校对 ProofreadReminder / 统计 StatsReminder（WritingPage.tsx:2715，有内容才出现，多条可同时叠放）；
  4. 章节头：标题 + 卷 chip + 状态/层级徽章；
  5. 编辑器：Tiptap EditorContent，写作动线（点击改名 / 就地切状态），zen 模式 680px 居中；
  6. 语料参考面板 + 底栏：编辑器正下方固定展示命中句（WritingPage.tsx:2783），底栏选区/今日/总字数。

另有 activeSetting 状态：选定「设定」后右栏整体替换为设定编辑区（人设 / 世界观 / 时间线 / 剧情线 / 伏笔 / 灵感六页签），工具栏仍留在顶部——此时界面语义从「正文编辑」切到「设定编辑」，但外壳不变。

3 · 问题点（重设计的依据）

3.1 布局与信息架构

① 左栏四个职责挤一栏，书架抢占高频空间

作品切换是低频操作，却以「书籍列表」形态常驻占 ≤45% 栏高（WritingPage.tsx:1475）；与之抢空间的章节树才是写作高频入口。栏宽固定 280px，设定/笔记列表信息密度受限。

② 编辑区六层堆叠，正文可视高度被反复挤压

工具栏 + 4 条提醒 + 章节头 + 编辑器 + 语料面板 + 底栏纵向排队。语料面板最高 240px，提醒条可 4 条同时出现，zen 模式虽隐左栏但提醒条仍保留（仅语料面板隐藏）——normal/focus 下正文往往不足一屏。

③ 视图矩阵复杂，「当前在哪一层」不可见

右栏 body/details Tabs × 左栏 chapters/settings/notes Tabs × activeSetting 三套状态组合出多种视图；activeSetting 时正文被整体替换但工具栏/外壳不变，用户容易把「设定编辑」误认为仍在写作。

④ 左侧三 tab 内部结构各自为政

章节 tab = 操作行+搜索+树；设定 tab = 列表+筛选+新建；笔记 tab = 列表+筛选。每 tab 顶部操作区形态不统一，缺少一致的三级导航心智（书 → 章 → 元素）。

3.2 交互与可发现性

⑤ 工具栏 35+ 图标无分组平铺

格式化 15 项与功能 20 项共用一个 flexWrap 行，无分组间隔、无文字标签，全靠 hover tooltip；屏宽不足时换行两次，工具栏占三行。功能密度接近「全部平权」，低频按钮（如快捷键、章导航）与高频按钮等高占位。

⑥ AI 能力 6 个入口无统一心智

AI 审视、AI 聊天、自动审阅、AI 续写、AI 润色、内联 Dialog 各自独立按钮/对话框；首轮体验者无法判断「该用哪个」。与「自动校对」「自动语料」并列，AI 边界模糊。

⑦ 语料参考面板推挤正文，输入即跳动

面板常驻编辑区底部（哪怕 4 条提醒条已占位），有命中即展开到 240px；每次输入刷新时高度变化、滚动位置抖动，打断了「选中即插入」的流畅感——功能正确，但舞台动线（typography 的专注感）被破坏。

⑧ 就地编辑与对话框两套模式混用

章节标题点击改名、卷 chip 就地切换、状态/层级徽章，与新建章/新建书/快照/AI 对话框并存；同一层级的同类操作（如「改章节名」vs「改设定名」）交互路径不一致，操作心智不统一。

3.3 视觉层级

⑨ 全域等权白底，无主次舞台感

左栏 280px 与右栏同为 Paper variant="outlined" 白底细边，工具栏/提醒条/语料面板仅靠 1px 分隔线区分；视觉上没有「正文是最亮的舞台、辅助信息退后」的层级。提醒条 4 种颜色（各自语义色）在写作区顶部形成「红灯区」，与语料卡片、徽章混排成杂色带。

3.4 工程结构（影响重设计的实施面）

⑩ 3263 行单文件巨型组件，UI 改动高风险

WritingPage.tsx 承载几十个 useState、内联巨型 JSX 与十余个对话框开关；任何布局级重设计都会触及这个文件的大部分区块。历史迭代中每次功能接入（校对、语料、灵感…）都在同一文件内叠加区块，是「堆叠感」的代码根源。

面板/对话框开关状态集中在页面内（statsOpen / chatOpen / proofreadOpen / notesOpen / snapshot…），弹层横向蔓延，无统一「工作台上下文」模型。

4 · 重设计方向与建议

方向 A · 三段式工作台框架（主方向，P0）

目标：把「一个页面堆六层」重构为「一个舞台 + 左右导航/辅助抽屉」，让正文始终是视觉与交互的中心，辅助信息按需出现、不推挤正文。

左列 · 导航与大纲（可折叠 240px/0）
作品切换（下拉/侧滑，不再常驻列表）
章节树（获得完整栏高）
设定 / 笔记 / 大纲（与章节同级 Tabs）
中央 · 写作舞台（不变宽，最多三层）
工具栏（分组收纳：高频单行 ≤10 项，其余入「Aa/⌘K」）
章节头（标题 + 徽章）
编辑器（唯一可滚动主体）
底栏（选区/今日/字数）
右抽屉 · 上下文辅助（默认收起，≤340px）
语料参考（输入自动检索，吸顶展示）
章详情 / 提醒汇总 / 伏笔·灵感
校对结果 / 统计速览
建议：右抽屉兼作「章详情」与设定编辑出口，消灭 activeSetting 整体替换正文的状态；语料面板从「编辑器下方固定条」改为「右抽屉首屏/边缘滑出」，输入时不再推挤正文。
  • 左列：作品列表收为下拉或窄 rail，章节树获得完整纵向空间；「设定/笔记」保持与章节同级 Tab，形成「作品 → 章节/元素」的一致二级导航；
  • 中央：正文独享滚动区域，提醒条改为「右上角待办胶囊」（统一黄色语义，点击展开右侧抽屉详情），不再在编辑区顶部叠 4 条彩带；
  • 右抽屉：语料参考、章详情、提醒、校对、统计统一收纳；语料参考保留「输入即自动检索 + 固定单一展示区」的核心语义，但展示位置从「推挤正文的底部条」变成「编辑部右侧吸顶抽屉」，插入正文一步到位不变。

方向 B · 工具栏重组（P0）

  • 按使用频次分层：行内仅保留高频 6–8 项（B/I/U/标题/引用/列表/高亮/链接）；格式全家桶（表格、插画、批注、排版、多色高亮）收进「Aa 格式面板」；
  • 功能区按语义分组：写作（章节导航、专注模式、速记）/ 检查（校对、查找替换、自动审阅）/ 资料（快照、导出菜单、快捷键）/ AI（审视、聊天、续写、润色合并为一个「AI」按钮 → 弹出菜单或面板）；
  • 引入 ⌘K 命令面板：把散落的对话框入口（统计、快照、全书搜索、导入、回收站…）统一为可搜索动作，降低发现成本，工具栏最终稳定在单行。

方向 C · 视觉层级（P1）

  • 三级背景：工作台容器（无强调）→ 左/右栏 Paper（极淡底 + 细边）→ 当前章节正文（纯白/最亮、maxWidth 走 typo.pageWidth，两侧留白）；
  • 单一提醒语义：4 种提醒条统一为「待处理」胶囊（黄色），严重性差异只在抽屉内用标签区分，消除编辑区顶部杂色带；
  • 模式连贯：focus/zen 不再只是「隐藏左栏」，改为「左栏收起 + 右抽屉隐藏 + 提醒胶囊淡出」的渐进沉浸，中间态可随时滑出。

方向 D · 工程重构配合（P1–P2）

  • 拆分 WritingPage：容器 + 分区组件（WritingSidebar / WritingToolbar / WritingReminders / WritingCanvas / WritingContextPane），对话框开关状态收敛进 writingStore 或独立 context，消除单文件巨型组件对每次 UI 改动的放大风险；
  • 语料参考独立化：现有接口（query + onInsertText + status 探针）已足够松耦合，重设计只需改挂载容器与呈现位置，不动检索链路，回归面小；
  • 独立窗口复用：写作台独立窗口直接复用重设计后的布局（无 SideMenu 环境已验证），三段式天然适配无 chrome 形态。

优先级路线（P0 先行，可逐项验收）

一句话结论：创作台（=/writing 写作台页）功能完备度很高（649 key、9 大功能域），主要矛盾不在能力缺失，而在 功能区挤一个栏、正文区堆六层、辅助信息与正文争舞台。重设计的核心动线是「正文上舞台、辅助进抽屉、入口被收纳」，以三段式框架 + 工具栏重组为 P0，工程拆分与视觉打磨跟进，即可在不破坏「输入即语料参考」等既有闭环的前提下完成整体焕新。
