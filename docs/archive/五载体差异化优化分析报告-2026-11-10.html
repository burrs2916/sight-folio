§1 五载体特征分析 —— 它们到底哪里不同

五个载体不是"同一篇文章的五种叫法"。它们在结构层级、时间坐标、AI 不许动的东西、离群判定、导出排版、自动诊断维度六个轴上各自不同——任何一轴共用小说口径，产出都是"一本小说式的诗集/剧本/日记"。这正是仓库注释里反复付过学费的结论（writingSchema.ts:10-11）。

维度散文剧本设计推论（本报告全部建议的判据来源）： ① 凡"AI 硬边界"一行的差异，都必须落到每一条 prompt 构建路径——漏一条，模型就会越界（把诗排成散文、替日记编记忆）； ② 凡"导出关键排版"的差异，都必须让 genre 走通从 UI 到渲染器全链路——断在中间，产物就是错的； ③ 凡"特有元素"的差异，决定 tabs/货架/面板该长出什么、该藏什么入口； ④ 凡"自动化诊断视角"，决定自动任务的预设与结论如何跨任务携带。

§7 自动化任务与上下文衔接：让上一任务的记忆被下一任务理解

结论：自动化"触发侧"机制已经很好（三道闸门 + 覆盖台账），"衔接侧"接近空白。写作域自动审阅（P3）复用的是代码扫描域的 AutoAnalysisPanel + autoAnalysisOrchestrator，跨任务记忆只有两条窄路：同会话 40 条消息窗口；结论被人工写成写作数据。

环节现状（已有）断点
触发trigger / cooldown / digest 指纹（内容没变不重复烧 AI）；轮转规则按覆盖台账补「从未问过的维度」；每次判定含跳过都落 ai_auto_analysis_runs（autoAnalysisOrchestrator.ts:8-14,163）预设与上下文供给（writingContextProvider 6 预设）小说口径 → 自动化对诗集跑的就是错的视角（联动 A-2）
执行agent 多轮工具循环，工具轨迹落 ai_messages.tool_calls下一轮组装历史时 tool_calls: None 一律丢弃（agent.rs:936-949，关键行 943）——上一任务"读了哪些章、核了哪些行"的中间事实不可再生
历史同会话内 40 条窗口，按 user 边界裁剪无摘要/压缩；跨会话零继承（新会话=新 uuid，只读本 conv，agent.rs:911,936）
结论代码扫描域有完整闭环：ai_auto_analysis_rules → runs → ai_insights（可 reconfirm 累计置信）→ ai_context_packs/sections（ai_repository.rs:1981-2210）写作域没有对应变体：无 task 表、无 memory 表（migration.rs:845-880,1014-1100）；工作台「行动项」面板数据源绑 activeAnalysisId（代码扫描），书场景恒为空 → 体检结论只活在聊天流里，关窗即散（workbenchPanelHooks.ts:759-761,978-998）
这就是「上次体检说这三处要改，这次它全忘了」的完整根因链。用户唯一能做的补救是复述或重跑——而 digest 闸门恰恰会因"内容没变"跳过重跑，自动化越守规矩，衔接断裂越显眼。

衔接方案：写作域「书级任务账本」（推荐架构）

不新造轮子——把代码扫描域已验证的 rule→run→insight→pack 闭环移植到写作域，用 genre 做视角参数：

  1. 书级行动项落库（补 D8/D10）：复用 ai_insights，以 moduleId=WRITING_MODULE_ID, scopeId=book.id 落库；前端「行动项/审阅结果」区块把数据源从 activeAnalysisId 换成「书场景按 book scope、代码场景按 analysis」（一个判据，两张脸同源，机制同 hiddenViewKinds）。每条 insight 带：来源命令（/体检、/形式…）、目标单位 chapterId、严重度、状态（open/采纳/忽略）。
  2. 跨任务携带（补 D9/D11）：每次 agent 组装上下文时（buildUserMessage 与自动分析 runner 两处），追加「上一轮未结结论」段：该书 open 状态 insights 的 top-N 摘要 + 上次 run 的 digest/时间。prompt 由模型"接着上次的账看"，实现「上一个任务的记忆被下一个任务理解」。
  3. run 摘要取代原始轨迹：不做全量 tool_calls 回放（token 不现实）；每个任务收尾生成 3–5 行结构化 run summary（查了什么/发现了什么/建议了什么）写入 run 记录，作为跨会话、跨任务的携带单位。会话历史窗口同理可升级为「滚动摘要 + 最近 N 条原文」。
  4. 体裁视角参数化：自动分析预设按 workbenchCommandSet(genre) 取支（复用斜杠命令集的 5 支诊断，它们本来就是各体裁的体检项），杜绝"给诗集自动跑伏笔审查"。
  5. 采纳即闭环：行动项被采纳（agent 改稿或人工改稿）→ digest 变化 → 下轮自动复检该项（reconfirm 语义），置信累计；连续两轮未复现自动关闭。这套语义在 ai_insights 已有实现可参照。
