⏱️ Sight Folio 时间线 ↔ 写作台联动分析报告

生成时间：2026-10-04 · 覆盖范围：时间线 pane / 剧情线 pane / 伏笔 pane / 灵感 pane ↔ 写作台（大纲/章节/设定/正文）全部联动链路

📋 执行摘要

整体评估：数据层联动坚实，状态层联动完善，但存在一处关键语义断层。

  • 已实现 所有核心写作实体（章节、设定、大纲 Beat、时间线事件、伏笔、剧情线）共用同一 useWritingStore，落库即全局可见。
  • 已实现 跨实体引用（伏笔挂章、灵感挂章、事件挂线、伏笔挂线）全部通过外键关联，双向可达。
  • 已实现 右栏选中态互斥机制保证「一次只编辑一个实体」，避免状态冲突。
  • 断层 最核心缺失：写作台「正文/摘要」字段 ↔ 时间线事件 event 字段之间没有自动同步。 用户在写作台写的内容不会自动进入时间线卡片，反之亦然——这是「时间线 tab 与其他 tabs 不能联动」的真因。

✅ 已实现的数据级联动（双向）

所有核心写作实体共用 useWritingStore（Zustand + Immer），落库后即时全局可见，不依赖手动刷新。

1. 章节 (WritingChapter)

  • 时间线 pane：事件挂章（chapterId）后，写作台章节列表实时可见该事件归属。
  • 伏笔 pane：埋设/回收章（plantChapterId / payoffChapterId）后，写作台章视图可反向查看伏笔列表。
  • 灵感 pane：灵感挂章转正后，outline.chapterId 非空，写作台大纲视图该 Beat 从"念头池"消失。
  • 跳章导航：时间线 EventChip「跳章」按钮调用 openChapterCarrierView(chapterId)，直达写作台对应章节编辑面。

2. 设定 (WritingSetting)

  • 时间线 pane：事件按 settingId 分轨，设定 pane 编辑设定名/描述后，时间线轨道标签即时更新。
  • 伏笔/灵感 pane：伏笔挂设定、灵感挂载出场人物/场景均通过 settingId 关联，设定 pane 编辑后所有引用处实时刷新。
  • 要素检查器联动：时间线/伏笔/灵感中点设定 chip → selectSetting(settingId) → 右栏切到设定详情。

3. 大纲 Beat (WritingOutline)

  • 灵感池：未挂章的 Beat（looseBeats）即「灵感念头」，灵感 pane 与写作台大纲 pane 读同一份数据。
  • 节拍绑章：写作台大纲 pane 把 Beat 拖入章节后，outline.chapterId 写入，灵感 pane 该念头自动消失（已转正）。
  • 出场人物/场景：Beat 的 extra.cast / extra.scenes 同时驱动写作台大纲视图、时间线事件编辑（EventChip 读取同字段）。

4. 时间线事件 (WritingTimelineEvent)

  • 数据共享：时间线 pane 与写作台共用 timelineEvents 数组，任意 pane 增删改后全局即时刷新。
  • 右栏编辑联动：点 EventChip → selectTimelineEvent(id) → TimelineSidePanels 右侧「详情」tab 出现编辑卡（at/event/绑章/挂线）。
  • 冲突检测联动：同轨 at 碰撞 / 跨章时间倒挂在计算后即时标红，右栏总览卡可点冲突行切口径。

5. 剧情线 (WritingStoryline)

  • 数据共享：时间线 pane（挂线）、剧情线 pane（管理/叙事/矩阵三视图）、写作台设定 pane 共用 storylines。
  • 双向引用：事件 storylineId 挂线后，剧情线 pane 的叙事/矩阵视图即时显示该事件；剧情线 pane 改名/改色后时间线轨道标签同步。

6. 伏笔 (WritingForeshadowing)

  • 数据共享：伏笔 pane 与写作台共用 foreshadowings，状态/描述/埋设回收章改后即时全局可见。
  • 跨章预警联动：埋设章→回收章跨度计算后，时间线 pane 右栏总览卡显示跨章预警数。

  • timelineViewMode: 'book' | 'chapter' | 'storyline' 放在 editorStore（非 pane 本地 state）。
  • 联动场景：右栏总览卡显示「跨章时间倒挂」冲突时，点冲突行自动切到 'chapter' 口径——主 pane 与右栏共享同一份状态，口径始终一致。

  • WRITING_CONTENT_SAVED_EVENT：写作台独立窗口保存正文后广播 content + wordCount。
  • 主窗口 applyExternalChapterContent 接收后，就地更新 chapters 数组中对应章的 content/wordCount，无需整表 reload。

❌ 关键断层点

核心断层 写作台「正文/摘要」↔ 时间线事件 event 字段：零联动

这是用户反馈「时间线 tab 与其他 tabs 不能联动」的最核心原因。
  • 现状：写作台（WorkbenchEditorPane）编辑的是 WritingOutline.summary 或正文字段；时间线 EventChip 显示的是 WritingTimelineEvent.event。
  • 问题：两个字段之间没有任何自动同步机制。用户在写作台写了"主角发现密室"，时间线卡片上该事件仍然是空的（或只显示旧值）。
  • 影响：用户必须在两个地方分别维护同一份内容，违背 DRY 原则，导致时间线成为"重复录入区"。
  • 代码证据：
    • TimelineSidePanels.tsx 第 496 行：DraftInput value={event.event} onCommit=...updateTimelineEvent —— 只写 timelineEvents 表。
    • 写作台编辑器：通过 saveChapterContent 或 updateOutline 写 chapters/outlines 表 —— 不碰 timelineEvents。
    • 两个表之间没有触发器、没有监听、没有同步函数。

语义断层 写作台 ↔ 伏笔/灵感：只感知实体存在，不感知语义关联

  • 现状：写作台大纲 pane 能看到 Beat（含 extra.cast / extra.scenes），但看不到「这个 Beat 是某条伏笔的回收点」或「这个 Beat 源自某个灵感念头」。
  • 问题：用户在写作台写正文时，无法直观看到「此处埋设了伏笔 A，需要在后文回收伏笔 B」的提示。
  • 具体表现：伏笔的 plantChapterId / payoffChapterId 只存了章 ID，没有精确到段落/句子级别；灵感的 chapterId 也是整章关联。

追踪断层 灵感分发后的反向链路

  • 现状：灵感分发「转时间线草稿」后，新建一个 timelineEvent，但原灵感 beat 的 extra 中没有记录「已转化为时间线事件 ID xxx」。
  • 问题：用户在时间线 pane 看到一个事件，无法一键回溯「这个事件最初来自哪个灵感念头」。灵感 pane 也不知道「这个念头已经被用掉了」。
  • 类似问题：灵感「转伏笔草稿」后，原灵感与新建伏笔之间同样缺乏反向追踪。

可加强 时间线 ↔ 正文编辑器的深度嵌入

  • 现状：时间线 EventChip 的「发生了什么」是纯文本输入框（DraftInput），不是富文本编辑器。
  • 可加强：如果用户希望在时间线 pane 直接写正文（而非仅写摘要），当前输入框能力不足。可以考虑在 EventChip 增加「展开正文编辑器」入口，或直接联动写作台的富文本编辑器。

🛠️ 具体改进建议

优先级 P0：修复核心断层（正文字段联动）

方案 A（推荐）：摘要单向同步

  • 在 WritingTimelineEvent 中新增 outlineId 字段（或复用已有关联）。
  • 当 Beat 同步到时间线时（BeatRow「同步到时间线」），把 outline.summary 写入 timelineEvent.event。
  • 后续用户在写作台修改 outline.summary 时，通过 store 监听自动同步到关联的 timelineEvent.event（单向：写作台 → 时间线）。

方案 B：双向绑定

  • 在 TimelineSidePanels 的事件编辑卡中，把 DraftInput 的 onCommit 同时写回 outline.summary（如果该事件由 Beat 同步而来）。
  • 风险提示：如果用户在时间线把 "主角发现密室" 改成 "主角发现暗门"，写作台的正文是否同步？需要确认业务语义。

优先级 P1：增强语义关联

  • 伏笔上下文标记：在写作台编辑器内联显示「🚩 伏笔 A 埋设点」/「✅ 伏笔 B 回收点」标记（类似 Word 批注），点击可跳转到伏笔 pane。
  • 灵感溯源：在灵感 pane 的「已分发」念头增加「查看去向」按钮，显示已转化的时间线事件 ID / 伏笔 ID，点击可跳转。

优先级 P2：时间线事件富文本能力

  • 在 EventChip 的 textarea 中增加「展开编辑器」按钮，调用 openWritingDesk 打开该事件关联章的正文编辑（如果已挂章）。
  • 未挂章事件：允许在时间线 pane 内直接写长文本（当前 textarea 只有 2 行，不适合写正文）。

优先级 P3：跨 pane 导航优化

  • 在时间线 pane 的 EventChip 中增加「在写作台打开」按钮（除了已有的「跳章」）。
  • 在伏笔/灵感 pane 的详情卡中增加「在写作台打开关联章」按钮。

📌 结论

Sight Folio 时间线与写作台的联动骨架已经非常完善。

  • 扎实：数据层共用 store、状态层互斥管理、跨实体外键引用全部到位。
  • 急需：唯一核心断层是写作台正文字段与时间线事件 event 字段之间没有自动同步，导致用户在两个地方维护同一份内容。
  • 可加强：语义关联（伏笔上下文标记、灵感溯源）和富文本能力可以进一步提升体验，但不影响基础功能。

下一步建议：优先实施「P0 摘要单向同步」（方案 A），在 WritingTimelineEvent 中建立与 WritingOutline 的关联，并通过 store 监听实现写作台 → 时间线的自动同步。这是解决「时间线不能与其他 tabs 联动」问题的最直接路径。
