sight-folio 写作台 · AI 能力增强方案

让 AI 帮创作者「写得好 · 写得真 · 学得会」

围绕三大目标——AI 辅助审核写作质量、规避 AI 味与情感空洞、借鉴语料库优秀作品的情感表达与写作手法——结合写作台现有能力设计可落地功能方案与优先级路线。

2026-10-13 · 现状盘点 + 行业调研 + 三组功能方案（A / B / C）+ P0–P3 路线图

1核心判断（先说结论）

现状的缺口

写作台的 AI 语料目前会生成与回答，但还不会审（诊断一段稿子差在哪）、防（约束输出不带 AI 味）、学（从语料库里教用户"这句话的手法是什么"）。这三件事正是创作者放弃 AI 辅助的最大原因：产物感情空洞、套路感强、学不到东西。

关键杠杆

把已有的三样资产串成闭环：语料库句子级结构化数据（切句 + 主谓宾 + 参考价值分层）、AI 审视预设闭环、校对面板的"问题列表 + 定位到句"范式。串起来就是：生成 → 检测 → 对照范文 → 改写，而不是继续堆孤立按钮。

最小改动优先

P0 阶段只改系统提示词 + 快捷指令模板（零新 UI、零架构），先把"人味约束"注入到语料参谋的每一次对话里；检测与范文对照等重功能放到 P1 逐步上，每一步都可单独验收。

方案一句话：把"语料参谋"从答问题的助手升级为会审稿、懂人情、教手法的写作教练——审（A 组）、防空洞（B 组）、学写法（C 组）三组功能沿"写作前 / 写作中 / 写作后"全流程布置。

3主流实践借鉴（调研结论）

3.1 「AI 味」的机器指纹——可检测、可量化的特征

综合行业对 AI 生成文本的鉴别经验，AI 味的核心不是"用了 AI"，而是以下四类可检测特征（来源见文末链接）：

机器指纹 具体表现 可做的检测规则
句式匀速 句子长度几乎一致、没有起伏，找不到真人写作的"呼吸感"与口语断点 句长方差过低 → 提示"节奏太平"
用词可预测 "首先其次最后""值得注意的是"等连接套路密集；高频模板词密度高 内置 AI 模板词库命中计数（中英双语）
转折模板 + 标点密集 "不是……而是……""更重要的是"反复出现；顿号、破折号、冒号堆积 模板句式正则匹配 + 标点密度统计
精致空洞 辞藻华丽但推动不了情节；关键情节一笔带过、无关处铺陈冗长；心理与环境描写堆砌 上述三项只能靠 LLM 层语义判断（情节 vs 描写配比）

3.2 规避空洞的提示词方法论——直接可用的约束规则

写提示词就四样：角色（你是谁）＋上下文（发生了什么）＋任务（要写什么、给谁看）＋约束（怎么输出、禁用哪些表达）——把"写得生动一点"这类形容词换成可执行的量化标准。

这条方法论可直接编译进语料参谋的系统提示：禁用模板连接词、禁止用形容词级评价代替具体描写、要求感官细节与明确立场、允许口语断点与不完美——即 B1 的规则内核。另一个共识是 Show, Don't Tell：直接陈述情绪（"她很伤心"）不如用动作、细节、对话呈现——这是 B3 顾问的核心算法。

3.3 成熟审校工具的交互范式——对标对象

工具 代表性能力 给我们的启发
Hemingway 颜色标注：黄=冗长句、红=复杂句、绿=被动句、蓝=副词；整体可读性评分 A2 检测结果用"可定位的问题列表"呈现，用户点一下跳转到句
ProWritingAid 重复词、陈词滥调、可读性、行文连贯性、用词老套/抽象无意义检测 "抽象词 vs 具体词"维度可并入 A2 词汇层
Grammarly 四个反馈维度：correctness（正确）/ clarity（清晰）/ engagement（多样）/ delivery（语气） 审校输出按维度分组给标签，比一条条平铺更易消化
对话式助手（ChatGPT / Claude / 国内写作助手） 选中文本就地改写、给可选方案、不强推唯一答案 B2 / C3 改写结果给"温和 / 浓烈"多版本而非单一答案

4方案全景：三组功能 × 写作全流程

主题 写作前 / 准备 写作中 / 落笔 写作后 / 复盘 核心价值
A · 审核质量 审校预设扩展（A1，选"审什么"） AI 味检测器实时查（A2） 情感弧线报告（A3） 知道"这段差在哪"
B · 规避 AI 味 —— 人味约束注入（B1）、情感浓度指令（B2）、Show-Not-Tell 顾问（B3） —— 落笔就有"人味"，不靠事后补救
C · 学写法 手法卡片与拆解（C1） 「找范例」对话（C2）、写法对照工作台（C3） —— 从语料库"学会"而不是"抄到"

三组是互补的闭环：B 在源头降低空洞概率 → A 在过程中发现问题 → C 用语料库的真实优秀写法给出"怎么改更好"的参考答案。其中 A2 与 C3 直接互喂：AI 味检测器圈出平淡句，写法对照工作台接住并给出范文级改写。

5方向 A · 审核写作质量：从"问一句"到"诊断一份稿"

A1 · 审校预设扩展 P1

目标让 AI 审视从"泛泛点评"变成按主题定向诊断：AI 味、情感浓度、节奏张力、逻辑连续性、人物一致性各成一档。
交互AI 审视对话框的预设下拉新增档位（沿用 aiContextRegistry 注册表 + 用户自选 Agent + 历史结论留存），不改变现有闭环。
实现只加 preset 条目与对应系统提示模板；"情感浓度"档的提示词要求输出浓度评分 1–5 + 证据句 + 提升方向，把模糊感受变成可执行反馈。
依托AiReviewDialog + useAiActions 既有架构，零新增组件。

A2 · AI 味检测器（本方案核心差异化） P1

目标仿 Hemingway / ProWritingAid：对选中章节给出"AI 味/空洞感问题清单"，每条可定位到句。
双层检测统计层（零成本、先跑）：句长方差过低、AI 模板词库命中（首先其次/值得注意的是/不是…而是…/更重要的是 + 英文模板）、顿号/破折号/冒号密度、抽象词比例（伟大/感动/美好…）。LLM 层（按需跑）：情节推进 vs 描写堆砌配比、关键情节被弱化、直接陈述情绪（Tell）未转化为细节（Show）。
交互问题列表（复用 ProofreadPanel 的 issueKey + 原文摘录 + 定位 onLocate 范式），每条带维度标签（节奏/用词/空洞/情绪直述）与严重度，可忽略误报。
实现统计层放前端或 Rust 侧纯函数（不占 LLM 成本，可离线）；LLM 层走既有 agentApi 发送链路；统计层句子数据用语料管线的切句结果。

A3 · 情感弧线分析 P2

目标整章"情绪起伏曲线"：按段落给出情感强度，标出平淡区（连续 N 段无起伏）、断层（情绪突变没铺垫），让作者看一张图就知道"哪里读者会走神"。
实现LLM 对每段打情感强度与主导情绪（依赖整章上下文一次调用）；前端渲染折线或区块热力条；与 A2 的"情节停滞"判断联动。

6方向 B · 规避 AI 味与情感空洞：从源头防，而不是事后救

B1 · 人味约束注入（先做，改动最小） P0

目标语料参谋的每一次生成/改写默认带"反 AI 味"人设约束，用户不用每次手动叮嘱。
约束规则（编译进系统提示）①句长长短交替，允许断点与不完美；②禁用模板连接词（首先其次/总而言之/值得注意的是…）；③具体细节与感官优先，禁止形容词级评价代替描写；④关键情节要有推进，不靠堆心理/环境描写撑篇幅；⑤给明确立场与个性表达。
实现仅修改 AiCorpusPanel 的 AI_CORPUS_SYSTEM_HINT（或追加一段规则常量），零新 UI、零架构改动，可立即发布。

B2 · 情感浓度与改写指令 P0

目标把"去 AI 味""升情感浓度"变成一键指令，替代用户手写复杂提示词。
交互在既有快捷指令菜单（上一轮刚上线的闪电按钮 + CMD_PRESETS 机制）追加两条模板：「去 AI 味改写」（先诊断本段 AI 味来源，再给改写版，并列出改了哪三处）；「情感浓度提升」（先指出缺哪种情感细节——感官/动作/心理/对话，再给"温和 / 浓烈"两个版本任选）。
实现加 i18n 键 + 模板文本，全部复用现有指令机制。

B3 · Show-not-Tell 顾问 P2

目标自动找出"直接陈述情绪"的句子（她很难过 / 他非常愤怒），提示转成动作、细节、对话来呈现。
交互选中文本 → Show-not-Tell 顾问 → 列出"情绪直述句 + 3 种展示式改写 + 一个来自语料库的真实例句"（联动检索，证明"这样写是成立的"）。
实现直述句识别可用统计层情绪词 + 主谓宾结构启发式命中，改写走 LLM；真实例句走 corpusApi.search（现有链路）。

7方向 C · 借鉴语料库优秀写法：从"拿来用"到"学会写"

C1 · 手法卡片与拆解视图 P2

目标语料命中卡片不只给"这句可以抄"，还教"这句为什么好、手法叫什么、怎么迁移"。
交互卡片附手法标签（白描 / 细节放大 / 短句顿挫 / 对话推进 / 心理独白 / 环境与情绪呼应…）；点击「拆解」展开：节奏分析 → 用词精妙点 → 情感逻辑 → 可迁移模板（句式骨架，可套自己的内容）→ 仿写示例。
实现手法标签可由 LLM 后处理批量打标并入库（一次全库批处理，句子级存储，复用切句/句序字段）；拆解内容点开时按需生成。
边界给出的是"手法 + 模板 + 仿写"，不直接提供整段可粘贴的原文——守住借鉴与抄写的界线。

C2 · 「找范例」对话能力 P1

目标用户问"给我一个写离别的含蓄表达"时，语料参谋先检索语料库命中真实原文再拆解手法，而不是凭空生成一段"AI 式离别"。
交互对话前先走 corpusApi.search（现有链路），把库内高相关句子作为"证据引用"，参谋的任务从"创作"降级为"引用 + 拆解 + 归纳手法"，最后仍可给出融合仿写。
实现改对话链路：识别"找范例类"意图（关键词或快捷指令）→ 前置 search → 把命中句打包进上下文再调用生成；命中卡片保留出处（已有）。

C3 · 写法对照工作台 P1

目标用户选中自己写得平淡的一句 → 从语料库找回一语义的"更优写法" → 逐句对照差异 → 生成标注手法的改写建议。
交互左侧自己的句子，右侧库内范例，中间列出差异点：节奏（短句停顿）/ 视角（人物在场感）/ 细节密度（具体名词 vs 抽象词）→ 底部给 1–3 版改写并标注"借鉴了 X 手法"。用户可逐版选用或继续调。
实现相似句召回：先按章节主题/关键词检索候选 → LLM/向量选择语义最贴近 1–2 句；差异分析一次 LLM 调用；全部复用现有检索与生成链路，新增一个对照视图组件。
与 A2 互喂A2 圈出的"情绪直述/空洞句"一键送入 C3，形成"发现问题 → 对照范文 → 落地改写"的完整闭环。

9风险与边界

鉴抄与借鉴的界线

C 组所有功能只给手法拆解、句式模板与仿写建议，不提供整段可粘贴原文；检索命中均带出处（现有能力），库内原文定位为"教学引用"而非"素材替换"。

检测的误报与可解释性

统计层规则可解释但必然误报（短句密集不等于 AI 味）；交互上每条问题都允许"忽略/不是问题"，且情感浓度给 1–5 分而非对错标签——风格无对错，只有浓度与选择。

成本与延迟

统计层零 LLM 成本先跑；LLM 层按需批量/节选触发，整章情感弧线一次调用；对话场景全部沿用现有流式链路，不新增等待体验。

10一句话下一步

建议的第一步：在现有 AiCorpusPanel 上直接落地 B1（人味约束）+ B2（情感浓度 / 去 AI 味指令）——这是唯一零新组件、当天可验收、且用户立刻能感知"语料参谋变聪明"的改动；跑通后再把 A2 检测 → C3 对照改写的闭环做进写作台右侧抽屉。
