3高优先级缺陷详解（建议 R1 处理）

影响数据可靠性或为可稳定复现的交互缺陷，均已完成逐行实证。

#1快照/草稿恢复竞态：旧内容覆盖新内容高 · 数据可靠
位置WritingPage.tsx 891-934
根因：恢复流程（快照恢复 / 草稿恢复）先写入落库、再刷新本地内容，但既不 flush 保存队列、也不清理防抖定时器与 pending 标记。随后 800ms 防抖自动保存触发时，会把恢复操作之前仍在队列里的旧内容覆盖写回——用户刚恢复的内容可能被旧草稿覆盖，且无任何提示。
修法：恢复入口统一走「先 cancel 防抖 + flush 未决保存 → 再执行恢复 → 重建保存队列」的原子流程；恢复期间置位抑制自动保存（共用互斥标记），恢复完成后重新初始化 pending 状态。改动范围集中在 WritingPage 保存状态机，辅以还原时序测试。
风险：保存状态机是全局核心链路，改动需全量回归快照/草稿/自动保存/关窗四条路径；建议同步补「恢复后 1.5s 内旧 pending 不再覆盖」的回归测试。
#2关窗保存失败仍销毁窗口：静默丢数据高 · 数据可靠
位置WritingPage.tsx 1165-1186
根因：窗口关闭流程 catch 分支只 log 错误，随后无条件执行窗口 destroy。落库失败（磁盘满、权限、进程写冲突）时用户毫无感知，改动即永久丢失。
修法（两档可选）：轻档——保存失败时阻止关闭、弹错误提示（尊重现有「error 类 toast 保留」偏好）；重档——提供「放弃并退出」二次确认。改动范围：WritingPage 关窗处理器 + 对话框文案。
风险：阻止关闭可能造成「窗口关不掉」的观感，需明确给出失败原因与重试/放弃两个出口。
#3⌘K 双监听器冲突：一次按键弹两层 UI高 · 交互 bug
位置WritingPage.tsx 586-590 与 1412-1421
根因：章跳转面板与命令面板各自注册 ⌘K window keydown 监听，两处都 preventDefault 但均不检查 e.defaultPrevented。按键一次触发两个面板同时弹出/切换，状态互相打架。
修法：收敛为单一 ⌘K 分发点（建议归并到命令面板），或两处都先判 e.defaultPrevented 短路返回；快捷键映射抽成常量表便于维护。改动范围小，回归成本低。
风险：需确认 ⌘K 的产品归属（章跳转 vs 命令面板二选一），改动前先与既定交互预期对齐。
#4对话框确认失败静默：删除/批量操作「假成功」高 · 反馈缺失
位置useDialogActions.tsx 196-200
根因：确认动作 catch 只 log 后无条件 setDialog(null)。删除章节/批量操作失败时用户看到的是「操作已完成」的假象，实际数据未变——是最危险的静默失败形态。
修法：失败时保留对话框并显示 error 反馈（沿用现有 error toast），提供「重试/关闭」两个出口；只有成功才关闭。改动范围：useDialogActions 确认流程 + 对话框文案。
风险：低；需为对话框错误态补 1-2 条测试。
#5设定卡自动保存失败静默：改动丢失无感知高 · 反馈缺失
位置WritingPage.tsx 1054-1067
根因：flushSettingSave 的 catch 只 log，不向用户暴露失败；卡片乐观更新后失败不回滚、无提示，用户误以为设置已生效。
修法：失败时回滚设定卡显示 + error toast（尊重「操作完成不加 success toast」偏好，但失败必须提示）；与 #4 共用一套「异步失败反馈」约定。
风险：低；需要注意乐观更新回滚时避免覆盖用户正在编辑的其他字段，建议按字段粒度回滚。

4中优先级缺陷详解（建议 R2 处理）

一致性与体验问题，单点改动、收益明确。

#6删除多步无回滚：树结构半完成态中 · 数据一致
位置writingStore 642-648
根因：删除章节的多个落库步骤用 Promise.all 并行执行，无事务包装与回滚。中途一步失败时，部分子数据已删、父结构未更新，树进入不一致状态且无提示。
修法：① 串行执行并逐步回滚已成功步骤；② 或先删父再兜底清理（视存储语义）；③ 失败时保留对话框走 #4 的错误出口。改动范围：writingStore 删除流程。
风险：需理解底层存储无事务时的回滚语义，建议用模拟失败注入（mock 第二次调用 reject）补测试。
#7手动备份不 flush：备份缺最后几秒改动中 · 数据一致
位置useExportActions.ts 278-295
根因：handleBackupBook 直接调用底层备份接口，跳过 flushSave。若用户在 800ms 防抖窗口内操作后立即备份，备份文件缺失最新改动。
修法：备份入口先 await flushSave() 再执行备份；与 #1 的保存队列互斥标记复用。改动 1-2 行 + 1 条顺序测试。
风险：无。
#8AI 上下文 chapterMeta 中文字面量混入英文模板中 · i18n/质量
位置useAiActions.ts 238-243
根因：构建 AI 上下文时，双语提示词模板外直接拼接中文字段/书面语标签（如「当前章节」类字面量与草稿内容），英文模式下的 AI 上下文混入中文，降低生成质量与一致性。
修法：元信息标签抽入 i18n key（zh/en），草稿内容保持原文；补齐英文 key 后跑 i18n 对称校验（现有校验已可拦截）。
风险：低；AI 上下文变化可能影响输出风格，建议与 prompt 模板一起审查。
#9导出菜单每次打开发 7 次 IPC 计数查询中 · 性能
位置ExportCountBadge
根因：导出项计数徽标在菜单展开时对每种导出格式各发一次 IPC 查询（约 7 次），无去重/缓存。频繁开关菜单产生可感知的 IPC 噪音，在慢盘上会卡顿。
修法：① 单次批量查询接口（若有）；② 或按会话缓存 + 「菜单展开节流」；③ 打开菜单后只查询一次并共享结果。
风险：低；注意计数时效性，缓存策略取「本次展开生命周期」即可。
#10每按键整页重渲染中 · 性能
位置WritingPage 状态分布
根因：corpusQuery / selectedChars 等高频变化状态提升在 WritingPage 顶层，正文输入每键触发全页（含抽屉语料面板、章节树等）重渲染。语料面板同时承担「输入即检索」高频逻辑，成本放大。
修法：① 语料面板自身状态局部化（面板挂载期内查询字符串只在面板内闭环）；② 或对与输入无关的下层组件做 memo/稳定引用。目标：每键渲染范围收敛到「正文章节 + 语料面板」。
风险：中；状态局部化可能牵动「折叠面板暂停检索、展开恢复」的既有行为，需回归该交互。
#11chapterQuery 跨书残留中 · 状态残留
位置WritingPage 381
根因：章节定位输入框的查询 state 不携带书籍上下文，切换书籍时旧查询词残留并继续作用于新书的章节过滤。
修法：切书（setActiveBook）时重置查询词，或在 state 中携带 bookId 做无效化。
风险：低。
#12命令面板 category 硬编码中文中 · i18n
位置WritingPage 1430-1498
根因：命令面板分组标签直接写中文字面量，未走 i18n；英文界面下命令面板仍显示中文分组。
修法：分组标签抽 i18n key；顺带核对命令描述文案是否全部走 t()。
风险：低。
#13硬编码 aria-label ×3、高亮色板无标签中 · a11y
位置WritingPage 2570 / 2600 / 2663；2878-2905
根因：若干图标按钮 aria-label 硬编码中文（英文界面读屏输出中文）；高亮色板渲染为按钮但没有可读名称，读屏用户无法识别颜色含义。
修法：aria-label 走 i18n；色板按钮补「颜色 + 是否当前选中」的可读命名（如「高亮色：红（当前）」）。
风险：低。
#14多处 async 导入/操作无 try/catch中 · 健壮性
位置handleImportTxt 等
根因：文件导入等异步流程未捕获异常，失败时错误冒泡到全局 unhandled，用户无反馈。
修法：统一错误边界约定——所有用户可触发的异步操作 catch 后走 error toast / 就地反馈；与 #4/#5 共用同一「异步失败反馈」模式。
风险：低。
#15导出系列无 loading 态，可连点重复导出中 · 交互
位置useExportActions
根因：导出/备份按钮点击后无进行中状态，慢速导出时用户连续点击会触发多次并行任务，产生重复文件与资源竞争。
修法：导出进行中禁用按钮或显示就地进度（按钮小 spinner 即可，不动布局）；完成后 1.2s 恢复。
风险：低；注意与「操作完成不加 success toast」偏好一致，用按钮态而非 toast 反馈。

6测试覆盖与工程风险

✅ 覆盖良好区
ChapterTreePanel / ChapterListPanel / CorpusReferencePanel / corpusQuery / SaveIndicator 等：纯 props 零 mock 测试，行为断言清晰，是后续改动回归的稳定基线。
⚠️ 未覆盖高风险区

act 环境为手写全局、PointerEvent 依赖 polyfill 注入，环境搭建与实现细节耦合，升级 React/测试库时需重点回归。
⚠️ 未提交改动
当前工作区 30+ 文件未提交（+3627/-1345），含 6 个未跟踪新文件。缺失 checkpoint 意味着 R1 修复若中途出问题较难回退；建议先行按功能拆分提交，再进入缺陷修复。

7分级改进路线图

按「先保数据、再修体验、后做工程」排序，每级给出改动范围与风险提示。遵循协作契约：每级正式动工前先与用户确认具体方案，不擅自加 UI 元素，默认数据保持精简。

R1 · 数据安全（#1–#5）建议 1–2 个迭代窗口
  • 统一保存状态机：新增「恢复/备份/关窗」共用互斥标记与 flush-cancel 原语，收编 #1/#2/#7 三个入口。
  • 异步失败反馈约定：对话框（#4）、设定卡（#5）失败必须可见，提供重试出口；沿用「成功不加 toast、失败必须提示」的现有偏好。
  • ⌘K 收敛单一分发点（#3）。

改动范围：WritingPage 保存链路 + useDialogActions + useExportActions 备份入口；预计 4-6 个文件、3-4 条新测试。风险提示：保存状态机改动需先做当前 30+ 未提交文件的关键性提交快照。

R2 · 一致性与体验（#6–#15）建议 2–3 个迭代窗口
  • 删除流程串行化 + 回滚（#6）；导出 loading 态（#15）。
  • i18n 补漏：AI 上下文元信息（#8）、命令面板分组（#12）、aria-label 与色板命名（#13）——复用现有对称校验兜底。
  • 性能：导出计数缓存（#9）、语料查询状态局部化（#10）、chapterQuery 切书重置（#11）。

改动范围：writingStore 删除链 + useAiActions + 命令面板/工具栏 + CorpusReferencePanel 状态边界；风险提示：#10 涉及面板开合与检索联动，回归时重点验证折叠-展开闭环。

R3 · 工程卫生（#16–#25）随重构持续消化
  • 死代码清理（#17/#22）、监听器解绑修正（#16/#23）、i18n 插值化（#18）。
  • 设计 token 抽取（#19）、稳定 key（#20）、类型断言修正（#24）。
