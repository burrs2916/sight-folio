AI 语料与写作辅助 · 还能怎么优化？

面向创作者（作者）的三条主线 —— 优化文章 · 优化语句 · 提供灵感 —— 基于当前已落地的 9 项能力做现状盘点、机会矩阵与优先级路线建议。

一句话结论

功能骨架已经完整 —— 从「检测」（AI 味、情感弧线、直述句）、「参考」（范例、手法卡片、写法对照）到「审校」（四档预设）都有落地，且全部挂在统一检索与对话体系上。真正的优化空间不在「再加一个能力」，而在把已有的检测结果变成可执行动作：让结论能一键应用、让素材能一键发展成正文、让受阻时能主动给灵感。

优化文章
审校结论 → 一键应用

四档审校预设能给出「1-5 分 + 证据句 + 方向」，但结论只读、改稿靠手动。做个「建议 → 定位原文 → 采纳改写」闭环，是投入产出比最高的一项。

优化语句
检测 → 批量润色流水线

AI 味检测与 Show-not-Tell 能“抓问题”，但一次只处理眼前几行。升级成「全文扫描 → 问题句清单 → 逐句 AI 改写 → 采纳/替换/忽略」，相当于内置拼写检查器的 Fix All。

提供灵感
灵感念头池 → AI 发展成文

浮动速记收集的灵感念头池已经存在，但目前只是一份背景材料。选中任意一条念头，「AI 扩写成段落 → 插入正文」即可打通创作闭环。

现状盘点 · 已落地的 9 项能力

以下全部经过源码确认（2026-10 现状），每项标注实现载体、能做什么、以及当前边界。

能力 实现载体 做了什么 当前边界 / 缺口
B1 人味约束 src/utils/aiCorpusChat.ts AI 语料对话注入 5 条人味约束（避免机械感 / 禁模板套话 / 具体优先 / 情节大于铺陈 / 给立场），覆盖对话与生成两条链路。 约束固定，不能按文风切换（网文 vs 文学 vs 知乎体）。
B2 快捷指令 AiCorpusPanel.tsx · aiCorpusChat.ts 「对话 / 生成」双模式；>>> 推荐句解析 → onInsertText 一键插入正文；按 dialogue / action / scene / auto 意图生成。 生成后即停，无「继续扩写 / 换个方向」的链式追问；插入是纯文本，不保留原位置语义。
A2 AI 味检测器 src/editor/proofread/aiFlavorEngine.ts 四类 issue：template（模板句）/ rhythm（节奏单调）/ punctuation（标点）/ vague（情绪直述），分 warning / hint 严重度，导出 VAGUE_WORDS 与 splitSentences。 检测在哪，改稿还得自己动手；无批量扫描入口。
C2 找范例前置检索 aiCorpusChat.ts · corpusApi.search 识别「找范例」意图 → 检索库内例句组装证据块喂给 LLM 作参考，答案带库内出处。 检索是 FTS5 关键词匹配，无语义向量 → 近义/意译召回弱；<3 字走 LIKE 有噪音。
C3 写法对照工作台 src/utils/craftCompare.ts · CraftComparePanel.tsx 选中句 → filterReferenceHits 按 referenceTier 分层取前 6 → 本地节奏拆解（±20% 阈值，longer/shorter/similar）+ LLM 语义维度对比 → 改写示范。 只对「选中句」生效；视角/细节密度等语义维度依赖每次重访 LLM；无采纳回写。
A1 四档审校预设 src/ai/providers/writingContextProvider.ts 情感浓度 / AI 味 / 节奏张力 / 逻辑连续性四档双语预设，材料含时间线、伏笔、灵感池、校对体检，经 launchModuleAnalysis → insights 闭环可回看历史结论。 审校范围默认「当前章」，无全书/多章批量审；结论只读，无「按建议改」。
C1 手法卡片 src/utils/craftTags.ts · CorpusReferencePanel.tsx 命中例句自动拆解：手法标签 / 节奏四档 / 情感 told-shown / 用词亮点 / 可迁移模板 / 仿写示范。 被动触发（拆解在「手法」toggle 下）；无「按手法标签主动逛库」的入口。
A3 情感弧线 src/utils/emotionArc.ts · EmotionArcPanel.tsx 段落按情绪聚类（8 类，强度 1-5），识别平淡区（连续 ≥2 段无情绪）与断层（剧变对/阶跃 ≥3），彩点折线图 + 红叉断层 + 段落点击定位。 单文档视角；无情绪来自词表的透明度说明；不提供「断层处怎么补」的建议。
B3 Show-not-Tell 顾问 src/utils/showTell.ts · ShowTellPanel.tsx 直述句判定（≤26 字 + 抽象情绪词 + 无细节）→ 8 类情绪各 3 条改写方向 + 示范改写 + 召回库内示范句。 检测与示范分离：给了「方向」但没给「一键换好词的按钮」。

底层资产盘点 · 优化可以踩在这些肩膀上

下面这些是已经存在、且被多项能力共用的基础设施 —— 后续优化多数不需要从零造。

5 个可直接复用的能力底座

  • 检索层：corpusApi.search（FTS5 关键词 ± LIKE 兜底）、referenceTier 分层（high / medium / low）、occurrences 位置定位、charCount / tokenCount 字数词数 —— 查得到、排得对、能定位。
  • 对话层：agent 会话 / 流式输出 / >>> 推荐句解析 → onInsertText 插入正文，一次打通「AI 输出 → 正文」。
  • 审校闭环：launchModuleAnalysis → insights 历史结论（WritingInsightsDialog / AiReviewDialog），结论可沉淀、可回看。
  • 灵感池：INSPIRATION_KEY='inspirations' 浮动速记 FAB 已在写作页落地 —— 收集已经解决，发展成文是空缺。
  • 编辑器定位：buildTextIndex + textRangeToPos 已被 A3 / B3 用来段落点击定位 —— 「建议 → 跳到原文」的技术已就绪。
⚠ 事实修正（避免后续踩坑）：语料库后端的句子级语言分析（jieba 词性 + 启发式主谓宾提取 + UDPipe 依存校正）历史上已被整体移除，现在 analysis.rs 只保留稳定的字 / 词数统计（见 src-tauri/src/domain/corpus/analysis.rs 模块头注释）。因此「本地主谓宾 / 句法成分」类优化不可行也不该做；句子级语义判断一律走 LLM 通道，本地只做词频、字数等可信统计（jieba 已内嵌用户词典，人名分词可用）。

优化机会矩阵 · 按创作者四大需求方向

共 12 个候选机会；标注复用资产、预估成本与优先级（P0 高价值低成本 → P2 大改动 / 依赖外部）。

方向一 · 优化文章（宏观结构）

O1 审校建议 → 一键应用改写

P1成本：中

四档审校预设产出「分数 + 证据句 + 提升方向」，目前结论只读。在 AiReviewDialog / WritingInsightsDialog 中给每条建议加「查看原文 / AI 改写 / 采纳替换」动作，用 push 到正文闭环落地。

复用：>>> 插入闭环 · buildTextIndex + textRangeToPos · insights 闭环 · agent 流式

O2 章节写作体检单（聚合报告卡）

P1成本：中

把四个纯函数引擎（AI 味检测 / 情感弧线 / 手法节奏 / Show-not-Tell）聚合成本章「写作体检报告」：AI 味问题数、情感断层位置、直述句密度、节奏分布 —— 一屏看清本章健康度，像审代码报告一样审故事。

复用：detectAiFlavor · emotionArc · craftTags · showTell 均为已测纯函数 · 前端图表技术（SVG 已用于弧线）

O3 跨章节 / 全书级审校

P2成本：大

人设一致性、时间线冲突、伏笔回收目前以「当前章」为上下文；升级为多章 / 全书批量审校，输出跨章问题清单（如「第 3 章埋的伏笔，第 9 章还没回收」）。

复用：writingContextProvider 的时间线 / 伏笔 / 人物材料 · 语料库 linkedTo / relations 同步经验（人物卡已有先例）

方向二 · 优化语句（微观润色）

O4 批量润色流水线（检测 → 清单 → 逐句改）

P1成本：中

「全文/选中段落扫描 → 聚合 AI 味 + 直述句问题 → 问题句清单（原文 + 类型 + 严重度）→ 逐句生成改写建议 → 采纳 / 替换 / 忽略」。相当于把 A2 与 B3 从「单次面板」升级成「批量处理流水线」。

复用：detectAiFlavor · showTell 批量入口 · agent 流式 · onInsertText / 替换 编辑通道

O5 口头禅 / 高频重复词检测

P1成本：低-中

统计当前章高频词 / 口头禅（「忽然」「然而」「勾了勾嘴角」类描写套路），给出出现位置与替换候选 —— 纯本地统计，不耗 LLM。

复用：jieba 用户词典分词（人名不再碎切）· CHARACTERS_KEY 人物名过滤 · 后端 count_words 口径

O6 句式单调 / 代词指代检测

P2成本：大

连续同句式开头（「他……」×N）、句长单调、代词指代不清 —— 需要语义理解，本地不可靠，只能走 LLM 批量分析（成本高）。若做，建议并入 O4 清单作为 issue 类型，而不是独立功能。

复用：O4 的扫描流水线 · LLM 通道

方向三 · 提供灵感

O7 灵感念头池 → AI 发展成段落

P0成本：低

灵感池已有（浮动速记 FAB），但目前只是审校背景材料。加「选中一条念头 → AI 扩写成 2-3 个版本的段落 / 场景 → 一键插入正文」：把「记下来」变成「写出来」。这是全套件中「复用链条最短、收益最直接」的机会。

复用：INSPIRATION_KEY 灵感池 · agent 流式 · >>> 插入闭环 · 现有速记 UI

O8 卡文雷达：主动给灵感

P1成本：中

检测「持续无输入 / 长时间卡在同段落」时，AI 侧建议入口提供三个剧情走向、库内相关金句、或「继续写」的下一句 —— 沿用现有 inlineContinue（续写），把被动等命令变成主动援助。

复用：inlineContinue 续写通道 · corpusApi.search 金句召回 · 编辑器光标/输入事件

O9 库内素材主动发现（按手法 / 情绪逛库）

P1成本：中

C1 手法卡片是被动拆解；可以做「手法画廊」：按手法标签（如「留白」「通感」「对话推进」）或情绪类型逛库，一次给 6-8 条例句 + 仿写示范，灵感不进则主动找。

复用：craftTags 标签引擎 · filterReferenceHits 分层排序 · 语料库 tags 多值标签

方向四 · 数据与体验面

O10 检索升级：近义召回（本地同义映射 → 远期向量）

P2成本：大

FTS5 是字面匹配，「找近义词的写法的句子」召回弱。轻量先行：导入同义 / 近义映射表做查询扩展；重方案：引入 embedding 向量检索（依赖外部模型与部署，需评估离线/在线取舍）。

复用：corpusApi.search 扩展入参 · jieba 词典 · 语料库 id 索引

O11 命中上下文还原（看句子先看语境）

P1成本：低

目前检索命中展示单句 KWIC，看不到上下文；作者难以判断「这句好不好、适不适合我」。按 occurrences 附近段落做「±N 句上下文」展开卡片。

复用：occurrences 位置 · corpus 后端可取下句 · CorpusSearchHit 已含段落定位

O12 个人语料收藏夹（好句沉淀 → 反向反哺检索）

P1成本：中

命中句可收藏至个人收藏夹并打标签，后续 filterReferenceHits 对收藏内容加权 —— 语料库从「全库共用」变成「越用越懂你」。写作台人物卡的 linkedTo / relations 同步已证明这类数据一致性方案可行。

复用：filterReferenceHits 排序钩子 · 语料库表结构调整（新增收藏表）· 人物卡同步经验

优先级路线建议

按「复用链条短、作者感知强、不动数据层」优先排序的落地顺序。

第一波 · 打通用例闭环（P0）

  • O7 灵感念头池 → AI 扩写 → 插入正文
复用链条最短（池子、流式、插入全就绪），改动集中在前端一个入口，作者体感强烈 ——「记下来的东西能变成字」。

第二波 · 把检测变成动作（P1）

  • O4 批量润色流水线（检测→清单→逐句改）
  • O1 审校建议一键应用改写
  • O11 命中上下文还原
  • O5 口头禅 / 高频词检测
四项都复用现有引擎与编辑通道，无数据层改动；把「指出了问题」升级为「给好了答案」，是作者价值提升最大的一波。

第三波 · 体验与纵深（P2）

  • O2 章节写作体检单（聚合报告）
  • O8 卡文雷达 · O9 手法画廊
  • O3 全书级审校 · O10 近义/向量检索
  • O12 个人收藏夹 · O6 句式单调检测
需要聚合多个引擎、涉及数据层改造或依赖外部能力，收尾阶段按需逐项落实。

三类值得注意的取舍

1 · 语法理解走 LLM，不走本地：句子成分类分析历史上因误判干扰创作被移除（analysis.rs 模块注释为证）。后续凡「语义 / 指代 / 句式」一律走 LLM 通道并给出「可编辑、可拒绝」的建议形态，本地只做词频、字数、位置等可信统计。
2 · “检测-建议”要做成动作而非报告：现有能力里检测与审校占了多数，但作者真正要的是「改」。所有输出建议的位置统一提供采纳 / 替换 / 忽略三态，把面板变成流水线。
3 · 灵感的入口要嵌入写作现场：灵感类功能（O7/O8/O9）应出现在「正在卡住、正要下笔」的地方（光标附近、速记 FAB、行尾建议），而不是藏在设置或深层面板 —— 这决定作者是否真的会用。
