# 正文格式规范 + 排版体检（2026-11-06）

李先生指出的真问题：**正文本身的格式不合格，编辑器既不提示也不报错**，于是成书的缩进、空格、分段全都不对。
这一层我之前完全没查——我只做了"设置能透传到产物"，没做"内容合不合格"。下面是实测证据与规范。

---

## 1. 实测：一个"缩进"在项目里有三套互不相通的口径

| 口径 | 出处 | 语义 | 导出侧读不读 |
|---|---|---|---|
| A 段级工具栏缩进 | `src/editor/extensions/textIndent.ts:68` → `style="padding-left: 2em"` + `data-text-indent="2"` | **整段左缩进**（块左边距） | **完全不读**（Rust 全库 grep `data-text-indent` / `padding-left` 零命中） |
| B 全局排版设置 | `typography.ts` 的 `indent` → 导出侧 CSS `text-indent: {}` | **首行缩进** | 读（R1 做的），但**默认 false** |
| C 作者手工硬空格 | 真实内容：`<p>&nbsp; &nbsp; &nbsp; &nbsp; <mark…>谢谢…</mark>…</p>`（第一章段首） | 什么也不是，只是四个不换行空格 | **原样进产物** |

统计（只读复制真库）：2 个有正文的章里就有 **4 个硬空格**、**1 处段首空白**。样本这么小都命中，说明这是习惯性写法，不是偶发。

### 由此产生的四种真实错误（都能复现）
1. **语义错**：A 是"整段左缩进"，B 是"首行缩进"。作者在编辑器里按工具栏缩进，看着像缩进，导出后 EPUB 里 `padding-left` 仍生效 → 变成**整段右边留白、首行不缩**，跟中文书排版完全两回事，而且**不报错**。
2. **丢失**：A 在 PDF/DOCX 通路上被彻底忽略 → 编辑有、产物没有。
3. **宽度漂移**：C 的 `&nbsp;` 宽度随字体与阅读器变（EPUB/Word/Acrobat 三种宽度），还会在行首造出错误断行与悬挂空白。
4. **双重缩进**：若同时用 A 又开 B，段首既有 `padding-left` 又有 `text-indent` → 缩进两倍宽。

## 2. 还有这些"静默通过"的格式问题（现在零校验）

| 类 | 具体问题 |
|---|---|
| 空白 | 段首空格/全角空格/`&nbsp;`；行内连续多空格；段末空白；用空 `<p></p>` 手动分段（导出成幽灵空段） |
| 分段 | 该分段处用换行 `<br>` 顶替段落（成书后无法正确缩进与分段）；一段过长（长段落影响阅读，中文经验阈值 ~500 字） |
| 中文标点 | 中文句里用半角 `,` `.` `?` `!` `:` `;` `()`；引号方向错（`"…"``"…"）；省略号用 `...` 而非 `……`；破折号用 `-`/`--` 而非 `——`；连续重复标点（`！！！`） |
| 英文标点 | 英文句里用全角标点；句号后 0 或 2+ 空格；用直引号 `"` 而非弯引号；`don't` 用直撇号 |
| 中西混排 | 中西文之间无空格（`使用Vue开发`）、数字与单位无空格（`共200人` 视规范而定）、全半角数字混用 |
| 结构 | 章正文里出现 `# 标题` 手写标题（与目录层级打架）；标题末尾带标点（成书排版惯例不加） |

## 3. 规范（单一真源，编辑器与导出共用一份）

**新增 `formatSpec`：中文（medium=novel 等）与西文分开，规则可执行、可报错、可一键修。**

| 规则 | 中文正文 | 英文正文 | 修法 |
|---|---|---|---|
| 分段 | 段间**不空行**，靠**首行缩进 2 字** | 段间**留段距**，首行**不缩进**（现代惯例） | 由 `formatSpec.lang` 决定导出侧 `text-indent` 与 `margin-bottom` 的**组合**（不再让 indent/段距两个开关各自乱设） |
| 段首空白 | **禁止**任何空格/全角空格/`&nbsp;`/`padding-left` 手工缩进 | 同 | 检出 → 一键删除并转成规范的段级 `text-indent` |
| 段级缩进 | 只允许一种表示：`text-indent`（em），存 `data-indent="2"` | 允许 0 或悬挂缩进 | 编辑器扩展改写为 `text-indent`（现 `padding-left` 语义要改） |
| 行内空白 | 连续空白折叠为一个 | 同 | 导出前规范化 + 写作侧提示 |
| 中西间隔 | 中 ↔ 西/数字之间补一个薄空格（盘古之白） | 不适用 | 可选开关，默认按语言判 |
| 标点 | 全角；禁则成对校验；`……`/`——` | 半角；句后单空格；弯引号 | lint 报点 + 一键替换（保守：只改明确无歧义的） |
| 空段 | 禁止空 `<p>` | 同 | 导出前删 + 写作侧提示 |
| `<br>` 分段 | 禁止用 `<br>` 冒充分段（连续 2 个以上必报） | 同 | 一键转 `<p>` |

## 4. 落地设计：三处都要有牙

1. **写作侧（这是"没有提示也没有报错"的直接答案）**
   - `formatLint(html, spec)` 纯函数 → 问题清单 `{rule, severity, count, excerpt}`；
   - 章详情面板 / 编辑器状态栏显示徽标（如 `缩进不规范 ×1 · 半角标点 ×3`），点开定位到段；
   - **一键规范化**（`normalizeFormat`）：可预览 diff、可撤销，只动明确无歧义的项（硬空格、空段、连续空白、标点），**绝不自动改语义**（如不自动分段）。
2. **导出侧（成书前最后一道）**
   - 渲染前统一走 `normalize`：段首手工缩进 → 删除；`data-indent` → `text-indent`；空段删除；空白折叠；
   - 交付回执里如实列出**修正了什么**（而不是悄悄改掉，那会让作者以为内容本来就对）；
   - 严重项（如 `<br>` 冒充分段）→ 默认**警告并写入回执**，提供"严格模式：不合格不放行"给认真要出版的用户。
3. **版式档联动**：中文档默认 `首行缩进 2 字 + 段间不空行`；西文档默认 `首行不缩 + 段距 0.8em`。上一轮那个 `indent: bool` 升为档内枚举 `firstLineIndent: none|twoChars|custom`，避免"缩进+大段距"这种自相矛盾组合。

## 5. 分期

| 期 | 内容 | 验收 |
|---|---|---|
| **F1** | `formatSpec` + `formatLint` + `normalizeFormat` 三个纯函数（前端唯一真源），带全规则单测（中英文各一套语料） | 用第一章真内容跑出 `硬空格缩进 ×1` 并一键修好 |
| **F2** | 编辑器/章详情接徽标与一键修（含撤销）；章保存时不阻断、只提示 | 徽标出现、修完清零 |
| **F3** | 导出侧规范化（Rust 侧同一规则的镜像实现 + 跨语言源码锁，沿用 `typographyExportLock` 的做法）+ 交付回执"修正清单" | 第一章产物里不再有 `&nbsp;` 缩进；回执列出改动 |
| **F4** | 段级缩进语义纠正：`padding-left` → `text-indent`（含历史数据迁移 + 向后兼容解析） | 编辑器/EPUB/DOCX/PDF 四处缩进一致 |

> F1/F2 不动导出，风险最低，且直接回答"为什么没有提示"。F4 涉及历史内容迁移，要单独立批次，不许顺手改。

## 6. 要你定三项
- **S1** 严格模式默认：**关**（默认警告 + 回执列明），还是导出前必须清零？
- **S2** 一键规范化是否含**标点自动替换**（我默认：含，但只替换无歧义项，且可在设置里整体关掉）
- **S3** 中西文之间自动补空格（盘古之白）默认：**按语言自动**（中文开、西文关）

## 7. F3/F4 落地 + PDF 空白页 P0（2026-11-06 第七批，浏览器与真产物核对驱动）

### P0：PDF 导出一直是白纸
`pdf_export.rs` 把 Type0 字体的 `/Encoding` 写成了**字符串**：
`Object::string_literal("Identity-H")` → 输出 `/Encoding(Identity-H)`；必须是**名字** `/Identity-H`。
后果：poppler/Safari/Chrome 一律 `Invalid Encoding in Type 0 font` → 字体装载失败 →
`No font in show` → **每条文字绘制被静默丢弃，每页全白，而导出仍报成功**。

证据链（改前 → 改后）：`pdffonts` 无字体 → `SightFolioCJK CID TrueType Identity-H emb=yes`；
`pdftotext` 抽不出字 → 中文正文完整抽出；光栅化深色像素 0% → 2.30%；回归 949 全绿。

### F3：导出侧结构层规范化（Rust 镜像）
`writing/format_html.rs`：段首手工缩进（**含 `&nbsp;` 实体**）、段末空白、空段、多余空白、
`<br>` 冒充分段；在 `render_export_file` 这**一个咽喉**做一次，六格式共用。
实测效果：PDF 各段段首空白从 **4/3/2/3 → 全部 2**；HTML 里 `&nbsp;` 归零；TXT 不再带硬空格。

踩到的两个坑（都留下了注释和测试）：
1. `&nbsp;` 在 HTML 里是 **6 个 ASCII 字符**，按 `char` 判空白一个都摘不掉 → 改成实体感知。
2. 判前缀用 `s.get(..8)` 会在**多字节汉字边界**返回 `None`，于是"摘到最后一个实体就停"，
   段首剩一个 `&nbsp;` → 改成按字符取窗口。

### F4：成书首行缩进由语种定，不再共用屏幕开关
`layout::indent_for_book(spec, zh_book)`：中文成书首行缩两字、西文不缩靠段距。
编辑器那个 `indent` 开关只管预览观感——实测它同时管两头时，产物缩进被 `&nbsp;` 牵着走。

### 一条新红线：导出侧不许擅自动内容
我最初在导出侧开了 pangu，结果 `快照原文A` 被插成 `快照原文\u{2009}A`，两条导出测试当场红。
**插薄空格 = 改作者的字**，只能由作者在写作台显式点「一键修」发起；导出侧只做零风险的
空白/分段规范化。标点/错别字永远归前端 `proofreadEngine`（词典只有一份）。

### 顺手修掉 TXT 两处我自己留下的缺陷
卷题重复排两次（分隔行本身已含卷名，又补一行同名标题）；章标题被按深度缩进（缩进属于正文段落）。
