## 2. 🔴 P0 新发现：圆角批次的「正确通道」在 MUI v9 里**不存在**

### 2.1 待办原文与它依赖的假设

`docs/设置功能推进记录.md` 第 29 轮待办 1（也是认领牌 `nextRoundMustRead` 写明第 30 轮在做的那一刀）：

> 圆角硬编码 194 处：MUI 用乘数 `borderRadius: 1`，**非 MUI 区用 `var(--template-shape-borderRadius)`**

这条口径的出处是 `src/theme/appearanceScales.ts:40` 与 `:251`，后者明确写着
「MUI **已经**把 shape.borderRadius 注入为 `--template-shape-borderRadius`」。

### 2.2 四条实测证据：这句话是假的

**证据 A —— 已安装的 MUI 是 v9.0.0**：`require('@mui/material/package.json').version` = **`9.0.0`**
（`package.json` 声明 `^9.0.0`）。

**证据 B —— 全包搜不到这个变量**：`rg -a -- "--template-" node_modules/@mui` → **0 命中**
（`-a` 已排除「当成二进制跳过」的干扰；`--template-shape-borderRadius` 同样 0 命中）。

**证据 C —— v9 真实的变量名是 `--mui-` 前缀**（node 现跑，非推断）：

```
createTheme({ cssVariables: true, shape: { borderRadius: 12 } }).vars.shape.borderRadius
  → 'var(--mui-shape-borderRadius, 12px)'
createTheme({ cssVariables: true }).cssVarPrefix  →  'mui'
```

**证据 D —— 本仓运行时确实走 vars 模式**：定向测试的 React 组件树里出现
`CssVarsProvider (createCssVarsProvider.mjs)` → `ThemeProvider (@mui/material/styles)`；
`dist/assets/index-8jG52V3r.js` 里能搜到 `--mui-palette-*` 字面量（vars 生效的产物），
而整个 dist 里唯一的 `--template-shape-borderRadius` 命中，就是 §2.3 那处**我们自己写进 inline style 的字符串**。
⇒ 全仓 `src` 对这个变量的引用只有 5 处，其中 4 处是注释/文档，1 处是真代码。

### 2.3 已经存在的活病灶（不用等批次执行）

`src/components/layout/SettingsDrawer.tsx:931`（设置抽屉「主题色彩」章节的原生 color input 色卡）：

```tsx
borderRadius: 'var(--template-shape-borderRadius, 4px)',
```

该变量在运行时**从未被定义** ⇒ 永远吃 `4px` 兜底 ⇒ **这张色卡的圆角不跟随「圆角风格」任何一档**。
它恰好长在用户点名的六个维度之一、且恰好长在设置抽屉里，观感就是「设置面板自己都不生效」。

旁证：`src/editor/renderers/canvasTheme.ts:92` 的注释写着画布卡片**原本**用的就是
`var(--template-shape-borderRadius, 6px)`，后来改成常量 `CV_RADIUS = "10px"` 并注明「不再跟随全局圆角设置」。
—— 有人已经撞过这堵墙，但把「不跟随」当成了设计选择，没有回头修通道，也没有更正档位文件里那句错的口径。

### 2.4 照待办原文执行会造成什么（本轮最大的风险）

批次若按「非 MUI 区用 `var(--template-shape-borderRadius)`」批量替换，结果是：

1. 194 处（批次实际范围见 §2.5）拿到一个未定义变量 → 全部退化成各自写的 fallback 常量；
   **「圆角风格」依旧不生效**，只是从「明显硬编码」变成「看起来接了通道」；
2. 随后按交接铁律「改完立刻进扫描锁」把 `var(--template-shape-borderRadius)` 写进 `settingsRound31.test.ts`，
   于是**一个死变量被锁成标准写法**，后面每一轮都会照着它继续扩散（锁越严，错得越稳）。

### 2.5 ⚠️ 执行前必须先做的分流：`sx` 乘数**已经**跟随档位

本轮实测 MUI v9 `styleFunctionSx` 的 `borderRadius` 语义（node 现跑）：

| `sx={{ borderRadius: v }}` | `shape.borderRadius = 6`（medium 档） | `shape.borderRadius = 20`（round 档） |
|---|---|---|
| 1 | **6px** | **20px** |
| 2 | 12px | 40px |
| 8 | 48px | 160px |

⇒ **`sx` / `styled` 里的数值圆角本来就是档位乘数，已经在跟随「圆角风格」，一个都不需要改。**
把 `sx` 里的 `borderRadius: 8` 换成 px 变量，等于把 48px 硬砍成 6px —— 大面积视觉回归。

按本轮扫描（正则 `borderRadius:\s*\d+(\.\d+)?\s*[,)}]`，排除 `src/theme/**` 与 `__tests__`）：

- 命中 **565 处 / 141 文件**（台账记的「194 处」是 15:2x 审计的更窄口径，两者不可直接比较）；
- 数值分布前列：`1`→150、`1.5`→107、`2`→64、`0.5`→43、`4`→39、`3`→34、`6`→28、`0.75`→26、`8`→23、`999`→15；
  **其中 0.5/0.75/1/1.5/2/2.5/3 这类小数与小整数几乎必然是 `sx` 乘数（合计 ≥437 处）—— 属「不用动」的一类**。
- 真正需要处理的只有**非 MUI 通道**：inline `style={{}}` 与 `React.CSSProperties` 样式辅助函数
  （`src/editor/renderers/*`、`src/editor/panels/*`、`src/editor/sceneEditor/*` 是主战场；
  `writingPanes.tsx` 的 63 处经抽 5 处验证，确实全是 `React.CSSProperties` 真裸 px ✅ 台账这条成立）。

**⇒ 分流的判据不是数值大小，而是「这个对象最终喂给 `sx` 还是 `style`」。**建议下一轮先跑一次
「按 `React.CSSProperties` / `style={{` 锚定的文件清单」，而不是按数值筛。

### 2.6 修法（一刀三处，顺序不能换）

1. **建一条真的存在的通道**：在 `appearanceScales.appearanceCssVars()` 里按档位注入
   `--app-radius-base: ${BORDER_RADIUS_BASE[borderRadius]}px`。
   该函数的返回值已由 `AppTheme.tsx:139-144` 逐项 `documentElement.style.setProperty` 落进 `:root`
   （`--app-font-scale` 就是这么通的），**不依赖 MUI 任何内部实现**，非 MUI 渲染区可直接消费。
2. **同步更正档位文件里那句错口径**：`appearanceScales.ts:35-41` 与 `:251-252` 的
   「MUI 已经把 shape.borderRadius 注入为 --template-shape-borderRadius」必须改成实测结论
   （v9 vars 前缀是 `mui`；`--template-*` 不存在；非 MUI 区用 `--app-radius-base`）。
   不改注释 = 下一轮照着注释再犯一次。
3. **翻转那条锁住旧判断的断言**：`src/theme/__tests__/appearanceScales.test.ts:105-106`
   现在写着「刻意不再注入 `--app-radius-*`：MUI 已把 shape.borderRadius 注入为 --template-shape-borderRadius」
   并用 `expect(Object.keys(vars)).toHaveLength(2)` 把通道封死。
   ⚠️ 红线「禁止为过测试改断言」在这里**不适用**：这条断言的前提是一个可证伪的事实（§2.2 四条证据），
   正确做法是**与第 1 步同一刀一起改**（断言改为 `toHaveLength(3)` 并断言 `--app-radius-base` 随档位取值），
   并在提交信息里写明「依据 + 证据」，而不是为了让它变绿而放松。
4. **顺带**：`SettingsDrawer.tsx:931` 与 `canvasTheme.ts` 的注释按新通道更正（画布那处是否回到跟随档位，
   先问李先生 —— 它现在被写成「独立视觉语言」，那是设计决策不是 bug，别擅自改）。
