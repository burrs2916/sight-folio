## 3. 🟠 新发现 A（P1，真病灶，一刀可收）：**「圆角风格」在 8 处 MUI 组件默认样式里被钉死像素**

这是本轮唯一能解释用户那句「圆角风格设了没反应」的实测成因，前五份审计都没查到这一层。

**取证（逐处实测）**：`src/theme/customizations.ts`

| 行 | 组件 | 钉死值 |
|---|---|---|
| `:22` | `MuiInputBase.root` | `borderRadius: 10` |
| `:36` | `MuiOutlinedInput.root` | `borderRadius: 10` |
| `:103` | `MuiFilledInput.root` | `borderRadius: 10` |
| `:119` | `MuiChip.root` | `borderRadius: 4` |
| `:149` | `MuiAlert.root` | `borderRadius: 8` |
| `:159` | `MuiMenuItem.root` | `borderRadius: 8` |
| `:177` | `MuiCard.root` | `borderRadius: 12` |
| `:186` | `MuiAccordion.root` | `borderRadius: 8` |

**为什么会失效（机理，两条都实测过，不是推断）**：

1. **`styleOverrides` 不是 `sx`。** `sx` 里的数字走 MUI 的 borderRadius 样式函数
   （`node_modules/@mui/system/borders/borders.js:40`：
   `createUnaryUnit(props.theme, 'shape.borderRadius', 4, 'borderRadius')`）—— 所以**组件里
   `sx={{ borderRadius: 1.5 }}` 这 447 处是真的随档位缩放的**（实测数值分布：≤3 的乘数 447 处 /
   引号 px 14 处 / `'50%'` 圆点 79 处 —— 后两类分别是不该缩放和无需缩放，本轮判它正常）。
2. **`styleOverrides` 是交给 emotion 的裸样式对象**，数字按 CSS 属性补 `px`。实测
   `@emotion/unitless` 的 unitless 键表里**没有** `borderRadius`（全仓 grep 零命中），
   所以 `borderRadius: 10` 落进 CSS 就是字面量 `border-radius:10px`，
   而 MUI 组件默认圆角来自 `theme.shape.borderRadius`（`AppTheme.tsx:89-91` 注入档位值）——
   覆盖层比默认层更具体，**档位被这 8 行彻底盖掉**。

**用户可见后果（逐条，不夸大）**：
- 选「直角」：卡片、输入框、Chip、Alert、下拉菜单项、折叠面板**仍然是 8~12px 圆角** —— 这正是
  「直角」这一档唯一想看到的效果，却恰好没发生；
- 选「全圆角 / 大圆角」：上述组件停在原值，界面变成「一半跟档位、一半不跟」的拼贴观感；
- 跟着一起失真的是 `src/pages/LibraryPage.tsx:886-893` 的页面级局部主题：它**刻意继承**
  `components: appTheme.components`（为了让色彩/字号在本页生效），于是这 8 行钉死的圆角
  **也被语料库页继承了一份** —— 一处根因，两处受害面。
- 设置抽屉自己的预览卡读的是 `var(--app-radius-base, 6px)`（`SettingsDrawer.tsx:985 / 1571`），
  预览是对的、界面不是 → 观感恰好是「设置生效了但界面不认」。

**建议修法（一次交齐，约 8 行 + 一把锁，不需要李先生的基线提交）**：
把这 8 处从裸数字改成按 shape 派生，且保持当前观感不跳（medium 档基准 6px，用乘数换算到最接近的现值）：

```tsx
root: ({ theme }) => ({ borderRadius: theme.shape.borderRadius * 1.5 /* ≈ 现 10px @medium */ })
```

- ⚠ `none` 档基准是 0（`appearanceScales.BORDER_RADIUS_BASE.none = 0`）⇒ 乘数写法在「直角」档**真的归零**，
  这正是想要的行为；`workbenchComponents.tsx:915` 那条注释已经立过同一口径（「刻意用乘数而不是
  `calc(var(...) + 6px)`：乘数在直角档真的归零」）—— 抄它，别另造。
- ⚠ 静态 CSS / 非 MUI 区仍走第二条通道 `var(--app-radius-base)`，全仓实测当前只有 **6 处**在消费它
  （抽屉 2 + `ReviewFindingsPanel.tsx:359` + `workbenchComponents.tsx:915` 等），这条通道不缺字段、只缺人用。
- 锁：`src/theme/__tests__/radiusScaleRound37.test.ts` 源码扫描 —— 判据「`src/theme/customizations.ts` 与
  `themePrimitives.ts` 内不得出现 `borderRadius: <裸数字>`」（否定式判据**先剥注释**，第 35 轮 §本轮自纠 4 那条坑）；
  再加一条渲染探针：档位 `none` 时 `MuiCard` / `MuiInputBase` 的计算样式圆角为 0。
