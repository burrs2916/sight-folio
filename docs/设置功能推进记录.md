### 真问题与根因（用户体感「设置点了没生效 / 重启又没了」的第 N 条路径，此前 33 轮都没审到）

`App.tsx` 首帧门控只等 `APPEARANCE_READBACK_TIMEOUT_MS = 1500ms`，到点放行界面（这个设计是对的：
读回走 IPC，某一项永远回不来不能把整个应用挂住）。但它留了一个窗口，而**七个域的 `init()` 全都在
await 之后无条件 `set(库值)`**：

```
t=0     init() 发出 settingsApi.get(...)          ← 内存还是内置默认
t=1.5s  门控超时 → 界面出来，可以点
t=1.6s  用户点「深色」→ setMode → 内存 {mode:dark} → 整份落库
t=3.0s  迟到的库读数回来 → 无条件 set → 内存被盖回旧的一套
```

三条独立伤害，本轮一次收掉：
1. **界面回退**：刚点的那一档自己弹回去（用户原话「设置了没生效」）。
2. **数据回退**：盖回之后他再改任何一项，写的是「旧内存 + 这一项」⇒ t=1.6s 那次改动在库里也没了。
   写作偏好域更隐蔽：消费点是「现取」（第 25 轮口径），连一次重渲染都不发生，用户完全看不见。
3. **连带维度被冲**：t=1.6s 那次写入以**未初始化的内置默认**为底做整份覆盖，库里其余维度
   （他很久前调好的 fontSize / 别的书的排版）当场被默认值抹掉 —— 这一条只有按字段并回来才修得回。
4. **写作偏好域还多一格**：库里没有这一键时 `init` 会走「首次使用写缺省档」⇒ 把用户刚选的禅模式**覆盖成默认**。

### 修法：一个 guard + 七处接线（订阅口径，不逐 action 手写 touch）

| 件套 | 落点 |
|---|---|
| ① 通道 | 新增 `store/settingsReadbackGuard.ts`：`capture()` 拍号 / `isStale()` / `dirtyKeys()` / `mergeStaleReadback()`（库为底、用户改过的字段为面）/ `isSameReadbackByFields()`（相同就不写库） |
| ② 接线 | 七个 store 各挂一次 `attachSettingsReadbackGuard`：theme / layout / typographyDefaults / writingPrefs / language / bookTypography / **appearance**（第七个刻意带上：它不在首帧门控里，竞态窗口比其余六域更长，第 20 轮记过的「重启才发现预设丢了」正是这条） |
| ③ 判据 | 订阅里只比**显式列出的落库字段**：`initialized` 之类非落库字段翻动不算「用户改过」（否则 StrictMode 双跑 init 会被判成改过、白写一次库）。`select` 取整份 state 的域必须显式 `countSameValueRewrite: false` |
| ④ 粒度 | 六域按字段；书级排版按**一本书**（`fields: null` = 键集并集，键就是 bookId，写死清单等于要求用户每建一本书改一次代码）；界面语言是标量 ⇒ 整域 |
| ⑤ 边界 | 被用户删掉的项在合并时**真删**（`delete merged[key]`），不留 `undefined` 值 —— 否则抽屉那句「N 本书单独调过排版」虚高（第 32 轮同因） |
| ⑥ 放行 | 无论走哪一支，`initialized` 一律置真。把界面停住的代价是白屏，比「闪一下」大，这条取舍不改 |

**为什么不做成「写库前先等 init」**：那会把 1500ms 兜底换成「点着没反应」，是把一个观感问题换成另一个；
真问题是迟到读数不该有整份覆盖权。**为什么不在每个 action 里写 `touch()`**：七域 30+ 个写入口，逐处接线必然漏
（第 24 轮反面样本），挂订阅后**新增 action 自动被覆盖**。

### 本轮解决的真问题

1. **`--app-font-size-base` 是注入了没人读的死变量。**
   `AppTheme` 每轮档位都往 `:root` 写它，全仓零 `var()` 消费者。现接进 `canvasEntity.css` 的
   `.ps-workbench` 字号通道作为「无排版档位时」的基准（medium 档 = 14px = 改前写死值，观感不变）。

2. **`data-app-motion` 同样是死属性，而且它掩盖了一条真实断链。**
   注释声称「静态 CSS 靠它跟随减少动效」，实际全仓没有 `[data-app-motion]` 选择器；真正生效的通道是
   `MuiCssBaseline` 注入的全局 `*` 规则（本来就不分区内外）。**所以属性删掉、注释订正**，
   顺手把审计里挖出的真断链补上：**CSS 的 `scroll-behavior:auto !important` 压不住 JS 显式
   `behavior:'smooth'`** —— 「减少动效」开着，项目树定位 / 扫描文件定位 / 校对结论跳转 /
   语料分组揭示 / 时间线新卡定位 / AI 对话滚底仍然一路平滑滑行。
   → 新增 `utils/reducedMotion.ts`（`isMotionReduced` / `currentScrollBehavior`，**现取**而非订阅，
   理由同写作偏好防抖：一次性动作不该为档位变化重渲染），六个消费点全部改成读档位。

3. **「字体大小」在界面 chrome 里基本无效：80+ 处裸 px 字号。**
   `AppTheme` 只缩放 MUI variant（`scaleTypography` 处理 rem），凡是自己写 `sx={{ fontSize: 12 }}` 的
   文字一个都不跟 —— 抽屉、顶栏、侧栏菜单、备份区、健康条全在这片。实测改写：SettingsDrawer 55 /

## 第二十轮（2026-11-02）：落盘可信 + 系统跟随不写盘 + 抽屉补全（含 2 个死控件/撞 id 缺陷）

> 本轮起点 = 第十九轮「下一轮待办」1～4 全部落地，另在实现过程中发现并修掉 2 个真缺陷（见 ③④）。

### 本轮解决的四个真问题

1. **「自动保存」这句话在写库失败时是不诚实的（待办 1）。**
   外观域五个 store 的 persist 原先都是 `settingsApi.set(...).catch(console.error)`：
   非 Tauri 环境 / IPC 失败 / 写库被占时，界面照样立刻变、抽屉底部照样写着「自动保存：每项设置即时生效」，
   作者关掉软件再打开才发现没记住。
   → 新增 **`store/settingsSyncStore.ts`** 作为设置落盘的统一可信层：
   - 写入失败**自动重试一次**（500ms 后）——瞬时故障当场自愈，不打扰用户；
   - 每个 scope 的真实状态留在内存（`idle | pending | saved | failed`）+ `lastSavedAt`；
   - 重试仍失败才弹一次 toast，并做 **15s 节流**（拖一下字号滑杆会连写十几次，不能刷一屏报错）；
   - 失败时留住「本来想写什么」，抽屉的**「重试」按钮重放最后一次写入**；用户已改新值则旧失败记录作废，不会重放过期内容。
   - 五个写入点（theme / layout / typography / language / appearance）全部改走 `persistSettings(scope, key, value)`，
     **不再有任何一处直接调 `settingsApi.set` 写外观域**。
   - 抽屉底部文案改为四态：`写入中…` / `已自动保存 · 13:46:20`（可对账的时间）/ 失败说明 + 重试 / 本次还没写过时才是原「自动保存」说明。

2. **「跟随系统」每切一次明暗就白写一次盘（待办 2）。**
   `App.tsx` 的 `matchMedia` 回调原先调 `setMode('system')`：档位没变，但 `config` 是新对象 →
   每次操作系统换明暗都落一次库、广播一次跨窗口事件，还会在落盘状态里留下一次「用户改了设置」的假记录。
   → `themeStore` 新增**不持久化**的 `systemMode` 字段 + `syncSystemMode()`（只更新内存，不落库、不广播，
   读数没变时连 `set` 都不做），并新增纯函数 `resolveModeWithSystem(mode, systemMode)`。
   → 消费点同步改：`App.tsx`（回调改调 `syncSystemMode`，订阅不再按 `mode==='system'` 分叉，挂载即校准一次）、
   `theme/AppTheme.tsx`、`pages/LibraryPage.tsx`（这两处原先在渲染期直接读 `matchMedia`，
   系统换明暗时 `useMemo` 根本不会重算 → 「跟随」档位下界面会停在旧明暗）。

3. **【真缺陷】正文默认排版的「段首缩进两字」是死控件。**
   `SettingsDrawer` 里那个 `Switch` 只有 `checked={typoConfig.indent}`，**没有 `onChange`** ——
   受控开关点下去纹丝不动（React 还会报 controlled 警告），是抽屉里最后一个看得见但按不动的控件。已接到 `setTypoConfig({ indent })`。

4. **【真缺陷】同一毫秒内连续另存两张外观预设会撞 id。**
   自定义预设 id 原先只取 `custom-${Date.now().toString(36)}`，而所有读写都走 `profiles.find(p => p.id === ...)` →
   撞 id 后改名/应用/删除只命中先那张，后存的那套等于凭空丢掉（React 列表同时报 duplicate key）。已加单调计数器后缀。
