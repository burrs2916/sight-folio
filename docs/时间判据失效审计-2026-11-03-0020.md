# macOS `find` 时间判据静默失效审计（第 53 轮 · 2026-11-03 00:20）

> 结论先说：接力棒里当作「轻巡检固定动作」的两条 `find` 时间判据，在本仓 macOS/BSD find 上
> **会在没有任何匹配的情况下静默返回空集、退出码 0** —— 正是任务书「工具陷阱」一节定义的
> 「把没跑成伪装成过了」。其中「源码指纹」那条从此刻起对**每一轮都是恒真空集**（假通过制造机），
> 必须换写法。本轮源码零触碰，只修判据与交接。

## 1. 缺陷 A：ISO 的 `T` 分隔符使边界时刻漂移

同一天花板上采样（00:15，`docs/` 共 3 个文件晚于 11-02 21:00），只改时间串写法：

| 写法 | 命中数 | 实际返回 | 判定 |
|---|---|---|---|
| `-newermt "2026-11-02 21:00:00"`（空格） | 3 | 草案 / 推进记录 / 认领牌 | ✅ 正确 |
| `-newermt "2026-11-02T21:00:00"`（T） | 2 | **漏掉草案（21:46:20）** | ❌ 边界漂到 (21:46:20, 00:00:25) 之间 |
| `-newermt "2026-11-02T21:00:00+08:00"`（T+TZ） | 0 | 空集 | ❌ 完全失效 |
| `-newer /tmp/sf-draft`（`touch -t` 造的参照文件） | 3 | 草案 / 推进记录 / 认领牌 | ✅ 正确 |

- 另一次实测：`-newermt "2026-11-02T23:45:52"` 返回空集，而同一目录同一时刻用 `-newer` 参照文件法返回 2 个文件。
- 带 `+08:00` 的写法正是认领牌 `nextRoundMustRead` 里推荐给下一轮的格式（`find docs -type f -newermt <上轮 releasedAt=2026-11-03T00:00:35+08:00>`）——**这条推荐本身是坏的**。
- 纯 epoch 秒（`-newermt "1793634000"`）会显式报错 `Can't parse date/time`，反而安全；**危险的是 `T` 形态：不报错、exit 0、静默给空/给漏**。

## 2. 缺陷 B：裸 `HH:MM:SS` 锚定「今天」，跨午夜即恒空

历轮源码指纹写法 `find src src-tauri … -newermt 21:46:54`：

| 采样时刻 | 判据 | 命中 | 语义 |
|---|---|---|---|
| 11-03 00:15 | `-newermt 00:00:01` | 2（推进记录 00:00:25、认领牌 00:14:41） | ✅ 正对照成立 ⇒ 命令本身在跑 |
| 11-03 00:15 | `-newermt 21:46:54` | **0** | ❌ 解析成 **11-03** 21:46:54 = 未来 ⇒ 无论谁改了什么源码都必空 |

⇒ 该判据的正确性完全取决于「本轮开工时刻是否晚于当天 21:46:54」。

## 4. 修正后的巡检固定动作（第 54 轮起照抄，勿再自创）

```bash
# 参照文件法（最可靠）：touch -t 格式为 YYYYMMDDhhmm.ss
touch -t 202611022146.54 /tmp/sf-base
find src src-tauri -type f \( -name '*.ts' -o -name '*.tsx' -o -name '*.rs' -o -name '*.json' \) \
     -newer /tmp/sf-base -print

# 若坚持用字面量：日期与时刻之间必须是空格，不能带 T、不能带 +08:00
find docs -type f -newermt "2026-11-02 21:46:54" -print
```

**强制正对照**（阴性结果不许裸报）：跑任何「零变更 / 零命中」判据时，同批再跑一条**必然有命中**的对照
（把锚点提前到某个已知写入之前，或 `-newer` 一个已知更早的参照文件）。对照不成立 ⇒ 判据判为没跑成，
本轮不得据此得出「空集」结论。
