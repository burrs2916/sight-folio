## 2. 🔴 新发现 A：字号「画布豁免」口径把写作内容面整体漏掉了

### 2.1 判据是怎么形成的（读锁文件，不是猜）

- `src/theme/__tests__/settingsRound32.test.ts:71` → `const CANVAS_DIR = 'editor/renderers/';`
- `src/theme/__tests__/settingsRound33.test.ts:13` → 「`src/editor/renderers/**` 不归界面字号
  （画布零 Emotion + 自有 zoom）—— 本清单不含」
- 该目录里确实登记了一条例外：`settingsRound32.test.ts:65-67` 给 `writingPanes.tsx` 的
  `'2px 2px 0 0'` 写了理由（**圆角**，页签指示条）。但**字号侧没有任何一条例外是逐处拍过板的**，
  整个目录是被 `CANVAS_DIR` 一刀切掉的。

⇒ 豁免的真实依据是「**文件住在哪个目录**」，不是「**这块界面是什么性质**」。

### 2.2 实测：豁免区 288 处里装的是什么

同一把正则 `fontSize:\s*\d+(\.\d+)?\s*[,)}]`（排除 `src/theme/**` 与 `__tests__`）逐文件计数：

```
src/editor/renderers/ 内 · 写作内容面（10 个文件）    208 处   ← 其中图标尺寸仅 4 处
  writingPanes.tsx                    133      ← 大纲/人物/世界观/篇目/立意/念头池编辑面
  WritingDocsRenderer.tsx              23      ← 文档树 + 篇目文本
  CastAnalysisPanes.tsx                15      ← 人物要素文本
  WritingChapterEditor.tsx             12      （4 处是 <Icon fontSize>，是图标不是文字）
  WritingDesignView.tsx                 7
  WorldbuildingAnalysisPanes.tsx        7
  WritingEntityRenderer.tsx             5
  WritingStudioPane.tsx                 4
  WritingWorkbenchRenderer.tsx          1
  ChapterPicker.tsx                     1
─────────────────────────────────────────────
src/editor/renderers/ 全目录           288      →  写作内容面 208 (72%) / 图形类 80 (28%)
```

**即：被当成「画布」豁免掉的字号里，72% 其实是写作文字界面。**

### 2.3 为什么这不是「画布自有 zoom」那档口径

逐条实测，不是推断：

1. `writingPanes.tsx:9-10` 自述：「零 Emotion：**纯 div/input/span + inline style**」+ 文件头
   「这些 pane 是**唯一的内容编辑面**，直接读写 `writing_chapters` / `writing_outlines` / `writing_settings`」
   —— 它是**内容编辑面**，不是图表渲染器。
2. `uiFontSize()` 返回 `calc(Npx * var(--app-font-scale,1))` 字符串，**sx 与 style 两条通道都吃**
   （18:16 审计 §5.2 已实测确认）⇒ 「零 Emotion」根本不构成豁免理由。
3. `--app-font-scale` / `--app-font-size-base` 由 `AppTheme.tsx:129` 注进 **`:root`**，
   CSS 自定义属性照常穿透进画布 DOM ⇒ 「在画布里」也不构成技术障碍。
4. **最硬的证据**：同一个豁免目录里的**正文纸面**早就接了档位 ——
   `canvasEntity.css:164`
   `font-size: var(--ps-body-font-size, var(--app-font-size-base, calc(14px * var(--app-font-scale,1))));`
   三层兜底注释（`:157-163`）写得很清楚：画布卡正文**认**「字体大小」档位。
   ⇒ 同目录内已经存在「画布里的文字跟随档位」的先例，**只有写作 pane 的 208 处没跟**。

**结论：这不是通道划分，是目录规则误伤。** 用户「切字体大小，正文那几块看着还是没反应」在本轮拿到
了此前 34 轮没有的量化落点。

### 2.4 动刀前必须拍的两个人工项（别直接批量改）

- **行高与行块高度也是写死 px**：`writingPanes.tsx` 里字号与 `height/padding` 同块出现，
  字号放大而行高不动 = 文本裁切，观感比「不生效」更差。⇒ 必须**同刀**处理尺寸耦合项，
  或先只做**不随行高约束**的标签/输入框子集。
- **画布 zoom 叠加**：这些 pane 在带自有 zoom 的画布卡内，档位 × zoom 会双重放大。
  建议口径：**写作 pane 跟「字体大小」档，不跟 zoom**（与 `.ps-workbench` 同规则），
  这条要李先生点头，因为它是**产品口径**不是缺陷。
- 配套：把 `CANVAS_DIR` 从「整目录豁免」改成**清单豁免**（列出真正的图形渲染器文件），
  否则下一轮任何新写作面住进这个目录就再次静默漏网。
