# 每轮固定流程（严格按序）
1. **现场复位（v2 取代「停轮报告」）**：git status --porcelain 出现非 docs/ 脏改动时，对照台账末条「下一片」判归属：
   a) 与队列某一片的代码特征吻合 → 视为上轮中断残留，跑基线：全绿则本轮接管、补完该片并 commit；有红则先保现场（`git diff > docs/archive/中断现场-<日期-时分>.patch`，未跟踪文件复制到同目录）再复位到 HEAD 干净，继续执行本片。
   b) 归属不可判 → 同样保现场后复位，继续执行本片。**任何情况下不许停一整轮等拍板。**
2. 基线校验：npx tsc --noEmit 与 npm test；上轮动过 Rust 再加 cd src-tauri && cargo check。任一红 → 本轮放弃推进改为修红；修不好就记台账结束（这是合法的零代码轮之一）。
3. 从队列取第一个未完成批次，切出**最小可验证**的一片。批次内可再切片，但不得改队列次序、不得并行铺多批。
4. 实现，并为该片行为补测试（断言必须可证伪，禁止空断言/占位测）。
5. 门禁三连：npx tsc --noEmit、npm run lint、npm test；动过 Rust 再加 cd src-tauri && cargo check 与 cargo test。**基线一律以台账末条记录的门禁数为准**（当前：eslint 408 problems (1 error, 407 warnings) 不许变多；vitest 256 文件 / 2898 条只许增加不许变红；cargo test 889 条只许增加不许变红）。任一门禁失败 → git reset --hard 回滚本轮全部改动并清掉新建未跟踪文件（回滚前若现场不可再生，先 stash 并在台账记 stash 号），台账记录失败原因与涉事文件。
6. 全绿 → git commit，message：feat(完结作品): B<批次号> <本片做了什么> <日期>。
7. 台账回写：批次号 / 本片 / 文件与增删行数 / commit 号 / 门禁实测关键行（原文） / 本片可见效果 / 下一片计划 / 仍卡项。
