## 1. 现状诊断（为什么必须推翻）

### 1.1 概念错误：一个页面同时冒充两个东西
- 「已完结」是书的**创作状态**：`writing_books.status = 'finished'`（合法码 `ongoing / finished / hiatus / abandoned`，见 `src/utils/writingSchema.ts:168`）。
- 「完结作品」实际是**导出文件登记表**：`completed_works` 字段为 `id, book_id, book_title, format, file_path, file_size, word_count, chapter_count, created_at, is_file_missing`。

页面只从后者起列表，两者零关联 → 「把书标成已完结，完结作品里没有它」（用户 2026-11-03 报障，已用数据坐实：该书 `status=finished`，产物表 0 行）。

### 1.2 六项结构缺陷（代码可核对）
1. **导出零选项**：`useExportActions.ts` 六个格式各一个硬编码 handler，范围永远是「全书未删章节」，无选章节 / 分卷 / 仅定稿 / 前后件 / 封面 / 页码 任何开关。
2. **书名是冗余副本且不回写**：`book_title` 在导出那一刻写死；后端 `save_completed_work` 只 stat 回填 `file_size`（`commands/writing.rs:651`），`list_completed_works` 只探测回填 `is_file_missing`（`:621`）。改书名后本模块的分组标题、搜索、排序**全用旧名**。
3. **产物路径是用户手选的绝对路径**：事后被挪走即 `is_file_missing`，档案必然烂掉。
4. **无版本**：一条记录 = 一个文件，无从判断哪个是最终稿，也无法回溯「这版给出去的是什么」。
5. **语义污染**：`backup`（整库 `.db` 备份）与作品导出挤在同一张表同一个 `format` 字段。
6. **产物质量约 70%**（`docs/产品推进与商业化分析.md:31`，引 2026-10-14 实测）：EPUB 无 CSS、DOCX 缺 `styles.xml`、PDF 无首行缩进与页码、PDF 表格输出为标签残渣，共 10 项 P0–P2。

### 1.3 边界（沿用既有商业化结论）
`docs/产品推进与商业化分析.md:91`：**不与平台自带作家助手抢「发布」**，要抢的是发布之前的成品化。故本模块**不做**任何平台上传/账号集成，只做「规格适配 + 交付包」。

## 2. 目标概念模型（三层，职责单一）

```
writing_books.status='finished'   ① 完结声明 —— 这本书我不写了（已有，语义不动）
        │ 1:N
work_versions                     ② 成稿版本 —— 不可变快照（本期新增，核心）
        │ 1:N
export_artifacts                  ③ 导出产物 —— 从某个版本生成（取代 completed_works）
```

三层各自成立、互不遮蔽：
- 标了完结但没有版本 → 成品页**如实显示**「已标记完结 · 尚无定稿版本」（这是本期修掉的那个 bug 的正解）。
- 有版本但没有产物 → 显示版本、导出入口待用。
- 产物**必然**挂在某个版本下 → 「这个 epub 是哪一稿」永远可回答。

`backup` 移出本模块（归设置里的备份职责），`export_artifacts.format` 合法值收敛为 `epub | pdf | docx | html | md | txt`。

## 3. 数据模型（DDL 草案，落在业务库 `data/config.db`）

```sql
-- ② 成稿版本（不可变快照的头）
CREATE TABLE IF NOT EXISTS work_versions (
  id             TEXT    PRIMARY KEY,
  book_id        TEXT    NOT NULL,
  seq            INTEGER NOT NULL,               -- 按书单调递增：1,2,3…
  label          TEXT    NOT NULL DEFAULT '',    -- 用户标签：试读版/交稿版/送审版
  note           TEXT    NOT NULL DEFAULT '',    -- 这一版改了什么
  is_final       INTEGER NOT NULL DEFAULT 0,     -- 全书至多一个 1（见下方唯一索引）
  chapter_count  INTEGER NOT NULL DEFAULT 0,
  word_count     INTEGER NOT NULL DEFAULT 0,
  content_hash   TEXT    NOT NULL,               -- 快照指纹：不可变校验 + 空版本拦截
  schema_ver     INTEGER NOT NULL DEFAULT 1,     -- 快照内部结构版本，未来渲染格式演进用
  locked_at      INTEGER NOT NULL                -- Unix 秒
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_wv_book_seq  ON work_versions(book_id, seq);
CREATE UNIQUE INDEX  IF NOT EXISTS ux_wv_book_final ON work_versions(book_id) WHERE is_final = 1;

-- ② 成稿版本的内容副本（D5：真不可变，正文明细表存）
CREATE TABLE IF NOT EXISTS work_version_chapters (
  version_id   TEXT    NOT NULL,
  sort_order   INTEGER NOT NULL,
  src_chapter_id TEXT  NOT NULL DEFAULT '',      -- 仅追溯，不作取数依据（原章可删可改）
  title        TEXT    NOT NULL DEFAULT '',
  content      TEXT    NOT NULL DEFAULT '',      -- 锁定那一刻的正文（与写作台同构的 HTML）
  kind         TEXT    NOT NULL DEFAULT '',
  parent_id    TEXT,                             -- 保留结构树，分卷/层级可复原
  status       TEXT    NOT NULL DEFAULT '',
  word_count   INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS IX_wvc_version ON work_version_chapters(version_id, sort_order);

-- ③ 导出产物
CREATE TABLE IF NOT EXISTS export_artifacts (
  id           TEXT    PRIMARY KEY,
  version_id   TEXT    NOT NULL,
  book_id      TEXT    NOT NULL,                 -- 冗余便于按书查；**书名不冗余**，一律 join 现取
  format       TEXT    NOT NULL,                 -- epub|pdf|docx|html|md|txt
  spec_id      TEXT    NOT NULL DEFAULT 'default',  -- 渠道规格预设（P2 落地，先留列）
  file_rel_path TEXT   NOT NULL,                 -- 相对作品库根，不是绝对路径
  file_size    INTEGER NOT NULL DEFAULT 0,
  status       TEXT    NOT NULL DEFAULT 'ready', -- queued|running|ready|failed|missing
  error        TEXT    NOT NULL DEFAULT '',
  origin       TEXT    NOT NULL DEFAULT 'export',-- export|import
  created_at   INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS IX_ea_version ON export_artifacts(version_id);
CREATE INDEX IF NOT EXISTS IX_ea_book    ON export_artifacts(book_id);
```

三条设计约束，直接对应现有缺陷：
- **不存 `book_title`**：书名一律从 `writing_books` 现取 → 从结构上消灭「改名不同步」（缺陷 2）。
- **存 `file_rel_path` 而非绝对路径**：换机器 / 改作品库根目录，只需重定位一次（缺陷 3）。
- **`ux_wv_book_final` 部分唯一索引**：把「全书至多一个定稿版」交给数据库保证，不靠前端自觉（D6）。

旧表处置：`completed_works` 改名保留为 `legacy_completed_works`（见开放项 Q1），新代码零引用。

## 4. 作品库目录布局（D4 + D7）

```
<作品库根>/                              默认 ~/Documents/SightFolio 作品库
  <bookId>/                              目录名只认 id，与书名彻底解耦
    v3/
      书名-v3.epub
      书名-v3.pdf
```

规则：
- **目录只用 `bookId`**，书名只出现在**文件名**里（用导出当时的书名渲染）。改名不迁移旧文件、不影响 `file_rel_path` 有效性。
- 根目录可在设置改；改根时只改配置值，不搬文件，随后按 `file_rel_path` 在新根下解析；解析不到即 `status='missing'`（沿用现有缺失提示语义）。
- 默认根目录不存在则创建；创建失败（无权限/磁盘异常）必须把错误如实抛给 UI，**禁止静默降级**回「另存为」。
- 「复制到其他位置」是交付动作，产物本体留在作品库内不动。

## 5. 主流程与状态规则

### 5.1 锁定一版（入口：写作台工具栏，D8）
1. 取当前**已落盘**的章节全集（复用写作台 `getFreshChapters` 语义：先冲掉未保存改动再取，避免锁到半稿）。
2. 计算 `content_hash`（规范化后的标题+正文+结构指纹）。
3. 与上一版 `content_hash` 相同 → **阻止并提示**「内容与 v{n} 完全一致，没有可锁定的变化」，给「仍然锁定」次级出口（防止用户明知无变化也要留痕）。
4. 事务写入 `work_versions`（`seq = max(seq)+1`）+ 全量 `work_version_chapters` 副本。
5. 勾选「作为定稿版」→ 同一事务内先把该书原定稿 `is_final=0`，再置新版为 1（原子，不允许出现两个定稿）。
6. 成功 toast 附「去成品页导出」跳转。

### 5.2 导出产物（入口：成品页版本详情，D8）
1. 选格式（可多选）→ 生成 N 个任务入**后台队列**，页面不阻塞写作。
2. 任务从 `work_version_chapters` 读**快照内容**渲染，绝不回读活的 `writing_chapters`（这是「不可变」的实际兑现点）。
3. 写入 `<根>/<bookId>/v<seq>/`，成功 → `status='ready'` + 回填 `file_size`；失败 → `status='failed'` + `error`，卡片上可**原地重试**。
4. 应用重启时，残留 `queued/running` 一律改写为 `failed('上次导出被中断')`（不留假进行态）。
5. 并发上限：同时最多 2 个任务（开放项 Q5）。

### 5.3 删除与清理
- 删版本：二次确认；若该版本有 `ready` 产物，需**显式勾选**「同时删除作品库中的产物文件」，默认只断记录不动文件。
- 定稿版被删 → 该书回到「无定稿」态（允许，不自动把别的版本提为正）。
- 书被删 → 版本与产物记录级联删除（文件保留在作品库，提示用户手动清理位置）。

### 5.4 「已完结」与版本的关系（开放项 Q2，默认值）
标完结**不强制**要求已有定稿版；但标完结时若一个版本都没有，给一次轻提示：「要不要现在锁定一版，避免后续改稿影响成稿」。成品页对「已标完结 · 无版本」的书**必须可见**。

## 9. P0 验收标准（逐条可测）

1. 书标为「已完结」后，成品页**无需任何导出动作**即可看到这本书（标完结→可见，闭环）。
2. 写作台「锁定一版」后，`work_versions` 增一行、`work_version_chapters` 行数等于当时未删章节数，且 `word_count` 与写作台字数栏一致。
3. 锁定后再修改正文并保存，**该版本的快照内容不变**（重开版本详情仍是锁定时的文字）。
4. 内容与上一版完全一致时锁定 → 被阻止并给出提示。
5. 把 v2 设为定稿后，`SELECT COUNT(*) FROM work_versions WHERE book_id=? AND is_final=1` 恒等于 1；且并发/重复点击不会产生 2。
6. 从 v1 导出 EPUB，产出的文件内容等于 v1 快照（即使书后来又改了 10 章）。
7. 导出多个格式时页面可继续写作；任务逐个可见进度；其中一个失败可单独重试，不影响其余。
8. 产物文件必然落在作品库根下；「取回」定位到的文件与记录一致。
9. 修改书名后，成品页、搜索、排序**全部显示新名**，而既有产物文件路径不变、仍可取回。
10. 修改作品库根目录后，产物按 `file_rel_path` 重新解析；解析不到显示「文件缺失」而非报错崩溃。
11. `export_artifacts` 中不存在 `format='backup'` 的写入路径；整库备份不在成品页出现。
12. 删除版本时未勾选删文件 → 记录消失、磁盘文件仍在；勾选 → 两者都消失。
13. 旧 `completed_works` 在新代码中零引用（grep 断言 + 结构回归锁）。
