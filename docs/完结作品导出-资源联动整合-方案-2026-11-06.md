# 完结作品导出 = 全资源装配：资源台账与推进方案（2026-11-06）

李先生的判断：**导出不是一个独立事件，而是对前面所有录入资源的联动整合**（目录/卷、排版、插图、本章资源、封面）。本文先把"作者到底录过哪些资源、每一项现在走到产物没有"逐条钉死，再给推进顺序。

配套：结构树/封面链路已在今天落地，见 `完结作品导出-目录树与封面-优化方案-2026-11-06.md` §7。

---

## 0. 一句话结论

**作者录过的资源有 7 类，今天真正走进产物的只有 2 类（结构树、书封/封面图 —— 而且封面只进了 EPUB）。排版设置是零联动：EPUB/PDF/DOCX 三套版式全部写死在代码里；逐章录入的本章人物·场景·关系·时间线（`extra.cast/scenes/relations/timeline`）零引用；书目元数据更糟 —— 作者/出版社/完结日期/ISBN 这个资源面根本还没被建出来（库里无列、UI 无入口、导出无消费），EPUB 的 `dc:creator` 至今硬编码成 `Sight Folio`。**

所以这不是"再补一个格式"的事，而是要把导出从**渲染函数**升级为**装配阶段**：一次把资源收齐、定格、校验，六格式共用同一份装配体。

## 2. 该长成什么样：把导出变成"装配 + 渲染"两段

今天的形状是：`render_export_file()` 里各格式各拿 `&[WorkVersionChapter]`，然后**各自再去看盘、各自写死版式**。资源一多就必然漂移（插图已有三份实现，就是证据）。

目标形状（一次装配，六处消费）：

```
assemble(version, book, app_settings, writing_settings, assets) -> BookAssembly {
  meta:        { title, author, publisher, completedAt, isbn, genre, medium, wordCount, language }
  layout:      BookLayoutSpec { fontFamily, fontSizePt, lineHeight, indentEm, justify, … }   ← writing_typography 唯一来源
  nodes:       [ { id, kind, depth, isVolume, title, bodyHtml, coverRef?, chapterExtras? } ]  ← 今日已建的先序结构行
  images:      [ { rel, abs, mediaType, role: cover|volume|chapter|inline } ]                 ← 一次收集 + 全局去重 + 同 basename 改名
  backmatter:  [ 人物表 / 世界观节选 / 本章关联 ]（默认关，勾选才装配）
  receipt:     { 用了哪些图、跳过哪些节点、缺哪张图、版式参数快照 }                             ← 写进 export_artifacts，UI 如实展示
  validate():  缺图 / 字体不可用 / 相对路径越界 → 任务 failed 并点名，绝不出"看着成功但缺资源"的产物
}
```

三条硬要求：
1. **资源收集只有一份实现**（现在的 `collect_asset`/`img_cache`/`collect_images` 三份合并进 `images`，HTML/TXT/MD 也吃同一份 → #7 的碎图问题一起解决）。
2. **版式只有一份判据**：`BookLayoutSpec` → EPUB/HTML 落 CSS，PDF 落布局常量，DOCX 落 `styles.xml`。字号/行距/字体/缩进从此在六格式里一致，而不是各自硬编码。
3. **导出回执**（receipt）落库：这本用了 12 张图、跳过 0 节、版式=行距 1.9/宋体 12pt。产物对不对，可对账，不靠肉眼猜。

## 3. 推进顺序（最小可见闭环优先）

| 批次 | 做什么 | 为什么排这 | 主要文件 | 可证伪判据 |
|---|---|---|---|---|
| **R1 排版设置进产物** | 读 `writing_typography` → 生成 `BookLayoutSpec`；EPUB `style.css` 参数化、HTML 快照同参、PDF 字号/行距/缩进吃它、DOCX `styles.xml` 吃它 | **最疼且最快看得见**：作者现在调字号行距完全无反馈。不动表、不动快照，风险最低 | `writing/mod.rs`、`pdf_export.rs`、`docx_export.rs`、`export_jobs.rs` + 新 `layout.rs` | 改设置（如 12pt→16pt、行距 1.9→2.2、段首缩进关）后重导：EPUB 解包含对应 CSS 值、PDF 内容流字号变、DOCX `styles.xml` 变；默认设置下产物与今天一致 |
| **R2 元数据与版权页** | 从零建这四列：`work_versions` 加列（或落 `extra`）→ 锁定弹窗给输入口 → `lock_version` 定格 → OPF 出 `dc:creator/publisher/date/subject/identifier`，`dc:creator` 不再硬编码；PDF/DOCX 补版权页 | 作者名写死是**当前产物里的事实错误**，比「少个字段」严重 | `work_version/mod.rs`、锁定弹窗、`writing/mod.rs` | 填作者「某某」重导 → OPF `<dc:creator>某某</dc:creator>`；不填 → 如实留空，不许拿 "Sight Folio" 冒充当作者 |
| **R3 装配层统一** | 建 `BookAssembly` + 合并三份图片收集 + 导出回执落 `export_artifacts` | 后面每条资源都要走它，越晚做重复越多 | `export_jobs.rs` 拆出 `assembly.rs`，三个渲染器改吃装配体 | 六格式解包对同一版本得到**同一张图、同一 role**；回执与包内文件逐一对得上 |
| **R4 插图定格进快照** | 锁定时把正文引用到的插图**定格**（版本目录 `resources/` 或快照表 `assets` 列，二选一拍板），导出只读定格件 | 现在锁定后删图 → 产物缺图/失败。`cover` 已定格，插图是**同一个坑没填** | `work_version/mod.rs`、`export_jobs.rs`、`library_root.rs` | 锁一版 → 把原图改名 → 重导产物仍完整；回执记录定格文件数与字节 |
| **R5 本章资源 / 设定卡成附录** | `extra.cast/scenes/relations/timeline` + `writing_settings` 生成 backmatter（人物表/世界观），**默认关**，勾选才装配 | 资源确实录了但没有出口；但"印不印进书"是作者的编辑决定，**不许默认塞** | `assembly.rs` + 新 backmatter 渲染 + 导出弹窗开关 | 勾选后 epub 末尾出附录且 spine/landmarks 可达；不勾选产物与今天一致 |
| **R6 渠道规格 `spec_id`** | 需求 §8 P2 的按渠道预设版式 | 依赖 R1 的 `BookLayoutSpec`，必须在后面 | 同 R1 | 选纸书 6″×9″ 出对应页面尺寸（PDF MediaBox 可验） |

**顺带补完上一轮遗留**：PDF/DOCX 的书封真图（台账 #5）、DOCX 用 `cover` 字段（#4）。它们与 R1 同批最省（都动同三个渲染器）。

## 4. 要拍板的四项

| # | 问题 | 我的建议 |
|---|---|---|
| **A** | 插图定格方式：**锁定时拷字节进版本目录** vs **只存清单，导出时读活资产、缺图即失败** | 建议**拷贝定格**。理由：你已把 `cover` 定格进快照，语义就该一致 —— 锁定即定格；否则"删图后旧版本导不出"，不可变性是假的。代价是作品库变胖（可在版本详情如实显示占用） |
| **B** | 排版设置粒度：全局一份（现在 `writing_typography` 就是全局）vs **书级覆盖** | 建议**书级覆盖 + 全局兜底**：一本书一种版式是出版常识（诗集与长篇行距不同），且 `writing_settings` 已是书级表，加一列零迁移风险 |
| **C** | 元数据（作者/出版社/完结日期/ISBN）落哪：`work_versions` **加四列**，还是塞已有的 `extra` JSON | 建议**加四列**。它们要进 OPF 参与检索与排序，塞 JSON 等于放弃约束；且版本不可变 —— 元数据本该随版本定格。输入口放**锁定弹窗**（锁定时顺手填），导出弹窗只读回显 |
| **D** | 附录（人物表/世界观/本章关联）默认开还是关 | **默认关**，导出弹窗里一个勾。写作产品的原则是"作者看得见什么就是什么"，附录是编辑决策不是系统默认 |

## 5. 不做什么

- 不做"智能补全"：不许根据正文猜作者/出版社，不许自动给章节配图，不许借图（封面不借图已是定稿）。
- 不在本轮动快照不可变语义、不动作品库归档规则（`export_artifacts` 一表两视图的结论是对的）。
- 不把 语料库 / 速记 / AI 对话 塞进产物 —— 它们是创作过程，不是成书内容（除非你另行要求"创作手记"类附录）。
- 不新增第七种格式；先把六种做对（需求 §10-4 的"六格式全通"还没真正达标）。

### 集成锁（这条最值）
`export_jobs.rs::作者的排版设置真的落进产物_epub与docx同源于设置库`：设置全局 18px/2.0/1em/宋体+Georgia，再给该书单独覆盖 22px → 跑真任务 → 解包断言 `OEBPS/style.css` 含 `font-size: 22px`、`line-height: 2;`、`text-indent: 2em`、双栈顺序，`word/styles.xml` 含 `w:sz w:val="33"`、`w:line="480"`、`w:firstLineChars="200"`。

**它当场抓出我写的两个真缺陷**（不是我预期错）：
1. `w:ind` 被拼进 `<w:spacing .../>` **内部** → OOXML 结构坏掉，Word 打不开；已改为 `w:pPr` 的兄弟元素并加了结构断言。
2. 半磅换算先 round 到整磅（17pt→34）再被上限夹回 33 —— 数值凑对、口径错；改为 `pt×2` 直取，22px=16.5pt=**33 半磅**。

### 语义改定（有一条旧断言被我改了，理由写在代码里）
EPUB 冒烟测原来断 `text-indent: 2em`。应用默认 `indent=false`（写作台上就是不缩进），按「作者看得见什么，产物就是什么」，**默认版式的产物现在是 `text-indent: 0`**；作者打开缩进才出 2em。断言已改成这个判据，并补了「默认不许偷偷开缩进」的双侧锁。别把它当回归改回去。

### R1 未完（如实）
- **PDF 正文版式仍未接**：`pdf_export.rs` 的字号/行距/段距是散在函数里的常量，且 `HEADING_LINE_H()` 等助手也吃同一批常量，局部遮蔽会造出"正文用新字号、目录/标题用旧值"的混合版式 —— 那是新缺陷，宁可单开一批把常量收成一个 `PdfLayout` 再切。
- **快照原生 HTML 的 `<style>` 仍是写死值**（`render_html_book`）；前端「另存为 HTML」模板同理。
- `writing_typography` 里的 `pageWidth` / `paper` 未参与产物（屏显概念，落产物属 R6 渠道规格）。

## 8. R4 落地记录：资产定格 + HTML 自包含（2026-11-06 第三批）

### 定格存哪儿：偏离原方案，理由如下
原计划"拷字节进作品库版本目录"。**实际改为主库 BLOB 表 `version_assets`**：
锁定是纯 DB 操作，而作品库根可能尚未设置、之后还可能被搬迁 —— 把文件写入耦合进锁定，
就会造出「没选作品库就不能锁版」这种卡死作者的事。字节随快照同库同事务，
版本才真做到自包含、可搬迁、离线可重导。
（`work_version_chapters.cover` 仍存引用，字节只在 `version_assets` 存一份，不重复。）

### 改了什么
| 位置 | 动作 |
|---|---|
| `migration.rs` | 新表 `version_assets(version_id, rel_path, media_type, bytes BLOB, missing, created_at)`，主键 (version_id, rel_path)，**两处建表都加**（结构锁要求） |
| `models.rs` / 仓储 | `VersionAsset`；`insert_version` 多收 `assets` —— **版本头 + 正文 + 定格图同事务**（只写正文不写图＝留一个以后必然缺图的版本；只写图不写正文＝孤儿字节）；新增 `list_version_assets` |
| `work_version/mod.rs` | `freeze_assets` / `freeze_assets_in`（base 可注入，测试因此**不碰用户真实 app 数据目录**）；`SNAPSHOT_SCHEMA_VER` 2→3 |

## 10. R2 横向铺开：署名行进全部格式（2026-11-06 第五批）

### 判据只有一份

## 11. R2 收尾：版本卡元数据 UI、dc:subject、HTML 版式（2026-11-06 第六批）

### 版本卡（完结作品页）
- 录了就把 `作者 ｜ 出版社 ｜ 完结日期 ｜ ISBN` 挂在版本行上；**没录就明说"本版未录书目元数据"**，不显示空壳。
- 按 `schemaVer` 给定格说明：`<2` → 该版锁在封面/插图定格之前，导出可能缺图；`==2` → 有封面引用但插图字节未定格；`>=3` → 不提示。
  这条纯展示提示是为了**不让用户把历史事实当成"功能坏了"**。
- i18n 3 键中英各补（词典是扁平键名，写成 `published.xxx` 会被词典锁打红——这次锁真的生效了）。

### 新增能力
| 项 | 说明 |
|---|---|
| `dc:subject` | 取 `writing_books.genre`（真实来源），与 creator/publisher/date 同一个条件拼装循环 |
| 快照 HTML 版式 | `render_html_book` 的 `body` / `p` 两条规则改由 `BookLayoutSpec` 生成；R1 至此覆盖 EPUB/PDF/DOCX/HTML（txt/md 无版式概念） |

### 抓到并修掉一个会让真机导出失败的口径错误
`export_epub` 里**书封走了定格查表**（`Some(&assets)`）。书封是"渲染当时现取"的书目展示属性，
不在定格集合内（定格只覆盖快照里的正文插图与各章/卷封面）。后果：
**凡是有定格件的版本 + 作者设过书封 → EPUB 导出直接报"图片没随本版本定格"而失败**。
这是最常见的真实组合，而我前面所有测试都没同时给"书封 + 非空定格表"，所以一直没暴露。
改为 `None`（现取），并补回归锁 `书封是现取资源_有定格件的版本设过封面也要能导出`——
用例自己造书封文件（不依赖 `/tmp` 外部文件、不碰真实素材库）。

> 教训：**"资源属于哪一类"必须有测试同时出现**。只测单类资源，交叉口径的错误永远测不到。
