# 诗歌（poetry）/ 剧本（script）体裁实装审计与刀序 · 2026-11-09

> 李先生：「工作室里的诗歌、剧本这两个题材我们都没有实现呢，你看一看我们如何提（升）」
> 本文只做审计 + 刀序，**未改任何代码**。行号均为本次逐条读到原文的位置。

## 0. 结论先行

1. **确实是没实现，而且不是"半成品泄漏"，是整条路关死。** 前端四道入口全部拿
   `ready: false` 挡着：建书向导里置灰、L1「＋」菜单里 disabled、左栏载体不可拖、
   设计卡落下来只有「建设中」。用户今天**根本建不出一本诗歌书或剧本书**。
   > 更正一条：§1 第 7 条的 `shelfFor` 复查后**当时没有生产消费点**（真正的拖源在 `writingPalette.ts`），
   > 那一条的实际用户影响为 0；诗歌实装时两条口径都一起对齐了，但影响不能记在 `shelfFor` 头上。
2. **库里没有历史包袱**（`sqlite3 -readonly data/config.db` 实查）：现存 3 本书 =
   `novel/serial` ×2 + `essay/collection` ×1，`genre` 里没有任何 poetry/script 值。
   → 实装这两个体裁**不需要数据迁移**，这是最省事的一点。
3. **后端和数据层其实早就支持**：`writing_books.genre` 是自由字符串
   （`migration.rs:1345` `genre TEXT NOT NULL DEFAULT ''`），Rust 侧 AI 建节点
   `default_root_kind()`（`tools.rs:3702-3705`）**已经把 poetry/script 归到「篇」**。
   真正缺的只在五层前端：术语层、货架、页签裁剪、设计视图、AI prompt。
4. **散文（2026-11-08 那两刀）已经把这条路趟通了**：`unitNameKey` /
   `hiddenViewKindsForGenre` / `shelfFor` / `ESSAY_SHELF` / `isEssayGenre` 都是现成的
   单源挂点。诗歌与剧本的"实装"= 给这些**已有函数各加一个分支**，不是重构。
5. 但**不能只把 `ready` 改成 true 就交差**（见 §4），那样得到的是一本挂着 11 个小说
   页签、首篇叫「第 1 章」、货架是「人设卡/世界观」、AI 开场白是「你是一位网文写手」
   的"诗歌"——比现在灰着更误导人。

## 2. 两个体裁真正不一样的地方（不是改名词就够）

### 诗歌
- **结构语言**：应是 辑/组 › 首（不是 篇/节）。
- **分行是本体**：正文编辑器是 Tiptap + `StarterKit`（`WritingChapterEditor.tsx:230-244`），
  段落 = 节、Shift+Enter 硬换行 = 行，这一层够用；但正文排版只有六个令牌
  `fontSize / lineHeight / paraSpacing / fontFamily / textIndent / pageWidth`
  （`typography.ts:311-316`）—— **没有"居中/不缩进的诗栏"这一档**，
  诗现在会被按散文排版（`indent` 一开就是首行缩进 2em）。要像诗，得给排版加一档
  → 属承载层，**动它之前报批**。
- **统计口径**：`countWords = getText().replace(/\s/g,'').length`（`:64-66`）只数字。
  诗真正有意义的是**行数 / 节数**，现在整条链路没这个概念。
- **该摘的页签**：世界观、剧情线、伏笔基本确定要摘；时间线是否保留请拍板。

### 剧本
- **结构语言**：剧 › 幕 › 场（现在拿不到这三个词）。
- **正文形态**：角色名 + 对白 + 舞台指示 三件套。好消息是 `writing-character`
  设定表可直接当角色表复用，**不用新造表**；坏消息是"对白版式"是全新的呈现层。
- **该摘的页签**：倾向摘 剧情线/伏笔/时间线，**保留** worldview（剧本有时代/场景设定）。
- **成本最高的一项**：对白版式 + 角色出场统计。这是六刀里唯一要新做组件的。

## 3. 建议刀序（每刀独立可验，小说侧逐字零回归）

| 刀 | 内容 | 是否碰承载层 |
|---|---|---|
| **刀0** | 拍板：术语表（首/辑、幕/场）、载体适配（poetry→collection？script→standalone？）、各自摘哪些页签 | 否，0 代码 |
| **刀1** | **诗歌·能用**：`ready` + `medium.fits` + `defaultLevels` 分离 + `unitNameKey` + `shelfFor`/`POETRY_SHELF` + `writingPalette` + `hiddenViewKindsForGenre` + 设计视图分支 + i18n | 否 |
| **刀2** | **诗歌·AI 层**：判据从 `isEssayGenre` 升级为「按体裁」；诗专用 prompt（保分行、不许散文化、不许解释诗意） | 否 |
| **刀3** | **诗歌·排版**：诗栏（居中/不缩进/更窄）+ 行/节数统计 | **是，先报批** |
| **刀4** | **剧本·能用**：同刀1 的剧本版（幕/场层级词、剧本货架、摘页签） | 否 |
| **刀5** | **剧本·AI 层**：对白/舞台指示 prompt，角色必须取自人设卡 | 否 |
| **刀6** | **剧本·对白版式** | **是，先报批** |
| **顺带** | KPI/语料口径按体裁（把散文那轮欠的第三刀一次做完，诗歌/剧本共用） | 否 |

## 4. 明确不建议的做法

把 `ready:false` 直接翻成 `true` 当"实装完成"。§1 的第 8/9/10/11 条会立刻全部现形，
用户会以为"诗歌功能就是拿来写散文的"。**闸口一开，后面每一处都得先跟上。**
