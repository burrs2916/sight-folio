FEATURE ANALYSIS

写作台 · AI 语料标签页功能分析

在现有「语料参考（自动匹配语料库已有句子）」基础上，新增独立 AI 标签页：支持 AI 自动生成语料，以及通过对话基于「整篇作品分析 + 本章分析」为用户提供参考决策建议。

范围：写作台右抽屉（创作台）语料参考区 方式：功能需求梳理 + 设计建议 + 界面衔接

一、背景与目标

现状一句话：写作台的语料参考目前只有一条能力链路——自动匹配语料库中已存在的句子。编辑器输入时自动取词，FTS5 检索，命中句以卡片呈现，可复制或插入正文，全程零手动输入、不打断心流。

本次诉求（用户原话拆解）：

  • 新增一个 AI 标签页：与「匹配语料库已有句子」并列，作为语料参考区的第二个 Tab。
  • 能力 A —— AI 自动生成语料：当语料库里没有现成句子可抄时，由 AI 基于作品与当前章节的上下文当场生成可参考的句子/段落。
  • 能力 B —— 对话式参考决策：用户可与 AI 对话，AI 结合整篇作品的分析和本章的分析，替用户判断"这句该怎么参考、该参考什么、是否生成/改写"，把"查语料"升级为"问语料"。
一句话定位：语料参考区从「检索器」升级为「检索器 + AI 参谋」——库里有就匹配，库里没有就生成，拿不准就问 AI 怎么参考。

二、现状梳理

2.1 现有语料参考链路（CorpusReferencePanel）

环节 实现
取词 extractCorpusQuery：以光标为界取前一段，按标点/空白切段取末段，再截尾 4 字符（MAX_CORPUS_QUERY_CHARS=4），重复串收敛为原子词
防抖 输入停顿 300ms 后自动检索（SEARCH_DEBOUNCE_MS）；翻页紧跟输入时补齐剩余防抖窗口
检索 corpusApi.search → 后端 FTS5（BM25 句子级）；书命中（书名/作者/分类）置顶 + 句子命中卡片列表，每页 8 条
呈现 卡片含：书名、章节 Chip、句子序号、重复出处、参考价值分层（high/medium/low）、字数统计；高亮命中词
动作 复制到剪贴板 / 插入正文（onInsertText 由调用方注入，组件不碰编辑器）
降级 corpus.db 初始化失败 → 可用性探针提示，不打断写作

2.2 承载位置（WritingDrawer · 创作台右抽屉）

语料参考以 embedded 形态铺满右抽屉剩余高度（宽 320px），顶栏为「章详情」入口 + 收起按钮，其上是提醒汇总区（伏笔 / 灵感 / 校对 / 统计，输入时自动折叠让位）。整体上排布为：

区域 内容 与语料的关系
抽屉顶栏 章详情按钮 + 收起创作台按钮 ——
提醒汇总区 伏笔 / 灵感 / 校对 / 统计四条提醒 输入时自动折叠，把垂直空间让给语料
语料参考区 CorpusReferencePanel（embedded） 本次改造对象
现状的边界：只能命中库里已有的句子。用户写的是新内容，FTS 命中率天然有限（设计上已把取词收敛到 2-4 字缓解）；一旦相关语料缺失，参考区就是一片空白，没有第二条出路。

2.3 可复用的 AI 基础设施（关键资产）

项目里已经具备一套完整、成熟、与本书场景深度耦合的 AI 能力，新标签页无需从零搭建：

资产 提供什么 复用点
WritingAiChatDialog per (agent, 书) 会话复用、首轮自动注入上下文、流式订阅、中断、新会话 对话骨架（可抽成嵌入式复用以避免重复实现）
buildChatContext 书名 + 当前章节 + 全书章节骨架 + 人物档案 + 世界观设定 + 本章正文尾部（双语） 「整篇作品分析 + 本章分析」的上下文几乎现成
runInlineWritingTask 续写/润色/改写/摘要四类内联任务，流式输出 生成类语料的执行通道（可扩展新 kind：生成参考语料）
buildCatalogCorpus / buildCharactersCorpus / buildWorldBibleCorpus 章节骨架、人物卡、世界观语料（纯函数、可测） 生成/对话上下文的拼装素材
workbenchContext（bookTopic） 题材随左栏切换的人设指令与上下文协议 AI 语料人设可按「语料参考」题材固化
agentApi / useAgentStore 会话 CRUD、agent 选择、流式通道、中断闸门 对话与生成共用一套通道，零新增后端
结论：本次方案的增量主要在 UI 层（Tabs + 两个面板） 与 上下文拼装/提示词；后端、会话、流式、agent 体系全部可复用既有实现，改动面可控。

三、方案设计

3.1 整体结构：语料参考区升级为双标签页

在 WritingDrawer 的语料参考区（CorpusReferencePanel 外层）引入 MUI Tabs，与工作台左栏（章节/设定/笔记）、右栏（正文/详情）的既有页签风格一致：

Tab 1 · 保持现有 CorpusReferencePanel 原样，零回归。
  • 输入即自动匹配库内已有句子（自动取词 → FTS5 → 卡片插入）
  • 行为、样式、拖拽宽度、分页全部不变
  • 仅在外层包一层 Tabs 容器，语料区高度语义不变
Tab 2 · 新增 AiCorpusPanel，含「生成」与「对话」两条子能力。
  • 生成模式：一键让 AI 基于本书 + 当前章节生成若干条可参考语料，逐条可插入
  • 对话模式：与 AI 对话，AI 基于整篇作品分析 + 本章分析给出"怎么参考"的建议
  • 两条子能力共用一个 agent 选择与流式通道

3.2 能力 A：AI 自动生成语料

设计点 方案
触发方式 显式一键（按钮「生成语料」），不随输入自动触发——生成有 LLM 成本且可能打断心流，与语料库 Tab 的"自动检索"形成对照；保留在需要时按需使用的控制权
上下文 复用 buildChatContext 拼装：书名 + 本章标题/字数/状态 + 全书章节骨架 + 人物档案 + 世界观设定 + 本章正文尾部（2000 字符），双语注入
生成目标 默认基于本章场景与基调生成 3 条风格一致、可直接改用的句子/段落；每条标记"结合了本章哪一类上下文"（场景 / 人物 / 世界观 / 前文语气）
执行通道 扩展 runInlineWritingTask 新增 kind（如 corpus-gen）或复用现有通道传自定义指令，流式输出到面板；零新增后端
结果呈现 每条生成结果一张小卡：正文 + 「插入」按钮（复用 onInsertText）+ 「复制」；支持再生成（换一批）
可选参数 轻量附加项：条数（1-5）、偏好（如"更克制/更有画面感"）、用途（对白/动作/环境）——默认留空即智能默认，不为难用户

3.3 能力 B：对话式参考决策

这是本次的核心增值：把"看命中句自己琢磨"变成"问 AI 怎么参考"。AI 的人设与上下文做针对性强化：

设计点 方案
人设 「本书语料参谋」：结合整篇作品分析（全书结构 / 人物 / 世界观 / 已写章节的总体风格）与本章分析（本章场景、节奏、当前段落的上下文），给出"这句是否可参考 / 参考哪句 / 直接引用还是改写 / 是否由 AI 重写一段"的明确建议
上下文注入 首轮消息自动拼 buildChatContext()（已有整篇 + 本章全部素材），后续轮次靠会话历史延续——与 WritingAiChatDialog 完全同一策略
会话复用 per (agentId, 书) 复用同名会话（如「语料参谋 · 书名」），换章不换会话；「新会话」按钮随时重开且重新注入上下文
参考衔接 对话中 AI 推荐引用的句子，如已命中语料库，可回链到语料库 Tab 定位（传回 query 切换 Tab）；AI 生成的句子同样可「插入」
快捷提问 预置 2-3 个常见场景快捷 chip（"这段该怎么参考？"“这章基调是什么意思，帮我分析”“语料库里没匹配到，帮我造两句”）降低冷启动门槛
用户提问

在 AI 语料 Tab 输入或点快捷 chip，如"我现在写主角重逢，库里有可参考的句子吗？"

上下文组装

首轮自动拼上书 + 全书章节骨架 + 人物/世界观 + 本章正文尾部；同时（可选）把当前输入的自动检索词一并带上

AI 分析并决策

AI 基于整篇与本章上下文回答：有无可参考 → 给原句或改写 → 或建议生成新句，并说明理由

落笔

用户对推荐结果点「插入」或「复制」，一句到位；不满意可继续追问

3.4 Tab 内布局与交互细节

  • 面板结构（自上而下）：agent 选择条 → 子能力切换（生成 / 对话 两个小 Segment 或叠加区）→ 内容区（流式对话气泡 或 生成结果卡片列表）→ 底部输入/操作区。
  • 生成区：顶部一行「生成语料」按钮 + 数量/偏好轻参数（默认收起，点开才显示），下方结果卡片流，底部「换一批」。
  • 对话区：消息气泡（用户右、AI 左）、流式渲染、中断按钮、Enter 发送 / Shift+Enter 换行、新会话；有会话历史可续聊。
  • 插入通路：生成结果卡片与对话中 AI 推荐句均带「插入」→ 复用父级 onInsertText（WritingPage 的 handleCorpusInsert），在编辑器光标处落笔，插入后卡片就地高亮（沿用现有 flashInserted 模式）；对话框场景可传到抽屉外。
  • 空态与降级：未配置 agent → 「去配置」引导出口（复用 writing.aiNoAgent / aiGoConfigure）；流式中禁用发送与切换。
  • 宽度约束：抽屉固定 320px，对话气泡与卡片文案保持紧凑排版；生成条数默认 3 条防滚动过长。

4.2 与既有能力的复用关系

WritingAiChatDialog → 对话骨架（抽嵌入式） buildChatContext → 整篇 + 本章上下文 runInlineWritingTask → 生成通道 agentApi / useAgentStore → 会话与流式 onInsertText → 插入落笔
衔接原则：语料库 Tab 的"自动匹配"保持自动驾驶不改语义；AI Tab 的生成/对话是用户显式触发的按需服务，两者互补不打架：有匹配看匹配，没有匹配可生成，拿不准可对话。

五、功能边界（本轮明确不做）

不做 原因 / 替代
AI 生成结果自动写入语料库 写入是重操作且污染「外部参考书籍」语料语义；本轮只做参考，未做"入库"；如需沉淀可后续做独立"我的语料"空间
随输入自动触发 AI 生成 成本与心流考量；保持显式按钮/对话触发
AI 直接替换正文段落（大段改写） 与内联 AI（润色/改写/续写）能力重叠；本 Tab 聚焦"生成/决策参考句"，整段改动走既有内联入口
拖拽调宽 / 独立栏形态 本 Tab 固定在 320px 抽屉内，保持现状可调性不动
跨章生成（自动扫描全书正文） 上下文预算与响应速度；本章尾部 + 全书骨架已足够支撑参考决策

六、落地实施计划（建议分 3 步）

P0 · 骨架与 Tab 切换结构性

WritingDrawer 语料区包 Tabs；「语料库」原样封入 Tab1；Tab2 先渲染 AI 语料面板骨架（agent 选择 + 空态 + 去配置出口）。验收：双 Tab 可切换，语料库行为与引入前一致。

P1 · 对话式参考核心价值

接入嵌入式对话：复用会话复用/流式/上下文注入，默认注入 buildChatContext（整篇 + 本章），快捷 chip 与「插入」按钮落地。验收：首轮对话带全书 + 本章上下文，AI 能给出明确参考建议并可插入。

P2 · 一键生成语料补全能力

生成模式落地：按钮触发 → 组装上下文 → 流式生成 3 条 → 卡片 + 插入/复制/换一批；可选数量与偏好参数。验收：空库场景下也能产出与本章基调一致的参考句并可插入。

测试与回归

  • 新增 AiCorpusPanel.test.tsx：Tab 切换渲染、无 agent 出口、发送禁用/流式态、插入回调。
  • 回归 CorpusReferencePanel.test.tsx 全绿（Tab1 语义不变）。
  • 全量 tsc + vitest + eslint 零新增问题，双语 i18n key 齐全。
